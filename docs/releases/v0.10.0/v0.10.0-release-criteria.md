# v0.10.0 — Release Criteria

Status: **Accepted — 2026-07-23** (v0.10 combined ADR+criteria consult; the five consult
decisions K1–K5 — the migration 0014 split, the FTS chunking + `ts_rank`/recency ranking, the
charter-bound-only scope, the read clamp reused from v0.8, and the confined-root enforcement as a
hard test — were CEO-ratified, alongside the four ADR ratification points R1–R4 that this document
implements). The single architecture ADR it depends on (**ADR-0066 — Layer 1 Live/Context Index**)
is already **Accepted**; acceptance of *this* document fixes the release intent. Future changes to
this document require a new ADR (criteria drift is a load-bearing decision — the v0.1.0–v0.9.0 rule).

Owner: War Room Commander (synthesis); Knowledge/Context Architect (the context source + the
deterministic FTS index + the incremental indexer); Permission Model Reviewer (SEC-33 — the lit
`agent-workspace` edge, same-grant containment, the confined root); MCP Gateway Reviewer (the one
control-plane tool — the gateway stays keyless); Audit/Evidence Reviewer (the per-read chaining +
the `context.read` vocabulary); Offline-Install Engineer (OI-17 — an api migration only; the new
tool rides the existing gateway binary).

This document defines what shipping **v0.10.0 — "Live/Context Index" (Layer 1 — governed,
deterministic, offline context retrieval feeding plan-time composition)** means. Every criterion is
*pass* (must be true), *block* (presence stops release), or *deferred* (explicitly out of scope,
with the trigger that promotes it back). The criteria are the exit gate for every v0.10.0 ticket: a
ticket is "done" when it closes one or more criteria here and breaks none.

---

## 1. Scope of v0.10.0

v0.10.0 builds **Layer 1** of `docs/architecture/memory-context-architecture-v3.md` — the Live/Context
Index (REQ-013, B-009) — deferred through four releases and given a **named consumer** for the first
time by v0.9: the composer's plan-time context. It completes the composer's read plane: it already
reads accrued **memory** (L2, v0.9); v0.10 adds a fresh, deterministic view of the operator's
**project context** (docs/runbooks/repo/tickets).

**Doctrine posture (settled at the scoping + ADR consults).** The index is **deterministic native
Postgres full-text search — zero embeddings, zero model dependency, zero egress, and ZERO new
third-party dependency** (the v0.8/v0.9 posture preserved; the indexer reads only operator-registered
*local* sources). **Layer 3 (reasoning retrieval — any embedding/AI dependency) stays hard-gated** and
is untouched. tree-sitter AST/code-graph is **deferred with a recorded trigger** (§14) — v0.10's
consumer plans governed shell commands, not code edits.

**Hard constraint (preserved).** Nothing new mints; the gateway stays **keyless** (ADR-0060); the
broker remains the sole SSH egress; **no new key, no new credential custody, no new egress path, no
new token-minting workload**. The gateway diff is **bounded to the catalog + one forward**
(`context.search` on the `run.launch`/`memory.read` pattern); the operator memory surface
(`/v1/memories*`) is **byte-identical to v0.8/v0.9** — L1 is a separate `internal/context` seam.

Concretely, on top of the v0.5–v0.9 platform, v0.10.0 delivers:

- **The context source** — an operator-registered local/mounted directory (docs/runbooks/repo/tickets)
  **bound to one charter**, its indexer **confined to the registered root** (SEC-33).
- **The deterministic FTS index** — native Postgres `tsvector` + GIN over chunked source content; no
  embeddings, no new extension/dependency; lexical (`ts_rank`) + recency ranking.
- **The in-process incremental indexer** — rides the api's existing background goroutine; mtime+size →
  hash incremental (no full rebuild); a per-source staleness signal.
- **The agent read plane** — the gateway `context.search` tool → pinned api forward, typed with the
  newly **enforced `agent-workspace` edge**; read-only, same-grant-scoped **by construction**, per-read
  chained.

**Out of scope** (→ §14): tree-sitter AST/code-graph (with the code-editing trigger); the `agent-repo`
edge (reserved for Git Intelligence); remote-target indexing; operator-shared / run-scoped context
sources; learned ranking / computed confidence; messages/chat indexing; Layer 3 (hard-gated).

The wedge is **one platform where an adaptive charter's composer reads a fresh, governed index of the
operator's project context it is entitled to, composes the next tick's plan grounded in it, a human
reviews that exact plan before anything runs, the governed engine executes it — and a source edit is
provably reflected on the next read without a full rebuild** (WD-10). Everything else exists to make
that true and verifiable.

## 2. WD-10 — the single load-bearing wedge (the demo)

**WD-10.** On a real (not mocked) stack, the composer plans grounded in fresh governed context. WD-10
comprises a **happy path** (1–8) plus six independent **live negatives**:

1. **A context source is registered and bound.** The operator registers a local/mounted directory of
   docs/runbooks/repo/tickets, **bound to an adaptive charter** (`workstream:<id>`), with the GOV-11
   consent copy in frame; the indexer's root is the declared directory only.
2. **The indexer builds the index — deterministically.** The in-process indexer chunks + `tsvector`-
   indexes the source (native PG FTS; no network, no embedding); the source shows an **up-to-date
   staleness signal**.
3. **The tick publishes (v0.9 machinery).** The charter ticks; a plan request opens (`plan.requested`).
4. **The composer reads memory AND context — both chained.** The composer (a real MCP client with a
   valid `aud=mcp-gateway` Bearer) calls `memory.read` (v0.9) and **`context.search`** (a query within
   its charter's grant); the latter returns ranked chunks from the bound source and chains one
   content-free **`context.read`** event per call (the query metadata, returned chunk ids, agent actor,
   the `agent-workspace` edge).
5. **The composer composes from fresh context and submits.** `plan.submit` passes plan ⊆ grant
   (SEC-29, the shared `LaunchBounded` core) and creates a **`proposed`** Run; `plan.submitted` chains.
6. **A human reviews the exact plan.** The operator opens the preview: every step's resource + sealed
   command is visible; the consent successor invariant holds. Approve → `pending`.
7. **The existing engine drives it and accrues.** The sequencer executes the approved plan unchanged;
   the terminal Run accrues its content-free pointer (v0.8 machinery unchanged).
8. **Freshness proves — and the chain proves it.** An edit to a source file is reflected on the **next
   `context.search` without a full rebuild** (the incremental indexer; the staleness signal flips then
   clears); `audit-service verify` — intact; the loop is present and content-free: `context.read`
   beside `memory.read` → `plan.submitted` → the `proposed`-Run resolution → `run.*` → `memory.written`.

**Live negatives (all live in the gate):**

- **N1 — cross-grant / foreign-source containment (the SEC-33 negative).** A second charter with its
  own bound context source exists; the composer's `context.search` **cannot** return any chunk of the
  foreign source; a `workstreamId` outside the caller's derived set answers **empty, never an error**
  (no oracle).
- **N2 — the indexer is confined to its root.** A symlink or `../` path inside a registered source
  pointing outside the declared root is **not** indexed/read — the confined-root guard holds (SEC-33).
- **N3 — staleness honesty.** A source edited but not yet re-swept surfaces its **stale** signal to
  both the composer (on read) and the operator (on the source view); the next sweep clears it.
- **N4 — per-read chained, fail-loud.** Every `context.search` chains exactly one `context.read` event
  **inside the read's transaction — no event, no data**; operator context management stays unchained.
- **N5 — no embedding / egress / network / new dependency.** The indexer + read make no network call;
  the index is native PG FTS only; `task licenses` shows **zero new third-party dependency**; L3 gate
  untouched.
- **N6 — injection still parks.** A plan grounded in indexed content still parks as a `proposed` Run
  for human review (the ADR-0065 always-park invariant carries — indexed content is untrusted).

**Regression guards (elevated this release).** **WD-5 + WD-6 + WD-7 + WD-8 + WD-9 all stay green**:
WD-9 especially (the composer now reads context *in addition to* memory — the v0.9 loop is
byte-preserved and simply gains the `context.search` read), and the operator memory surface stays
byte-identical (WD-8). The chain stays intact end-to-end.

**This demo (happy path + N1–N6) is the release gate** — built as an extension of the `tests/e2e` live
harness and re-run (full scope, K-installed) on the installer-produced stack.

## 3. Capability-edge security (must-pass)

Every boundary stays gated by `packages/go/middleware` `RequireCapability`. v0.10.0 **enforces the
reserved `agent-workspace` edge on exactly one path** (the `context.search` tool + its pinned forward)
— the canonical edge *set* is unchanged (ADR-0046 preserved); `agent-repo` stays reserved for Git
Intelligence.

- **SEC-33 (block) — the context-index invariant (the release's named invariant).** Agent
  context-index access is **read-only** (no agent write path; indexing is a machine sweep of
  operator-registered sources); the readable set derives from **the caller's own live grants by
  construction** (its grant's charter → the sources bound to that charter — never a caller-supplied
  path, never a foreign charter; out-of-set → empty, no oracle); the indexer is **confined to a
  registered source root** (no path traversal, no symlink-escape, no out-of-root read); **every
  agent-plane read is chained** (`context.read`, content-free, fail-loud in-tx); and **every
  agent-composed plan parks** as a `proposed` Run before any step executes (the ADR-0065 invariant is
  L1's injection control). N1/N2/N4/N6 are its live negatives; the operator `/v1/memories*` surface is
  byte-identical to v0.8/v0.9 (L1 is a **separate** seam).
- **SEC-32 / SEC-29/30 (block, carried).** The v0.9 adaptive invariant and plan ⊆ grant are unchanged;
  `context.search` adds a *second* read the composer makes, gated by the same grant, and mints nothing.
- **SEC-20/21/25/26..28/31 (block, carried).** The gateway stays keyless — `context.search` is a
  forward minted with the gateway's own service token to a subject-pinned api route (the `memory.read`
  pattern); no foreign-edge mint; broker/connector pins unchanged. The gateway diff is **catalog +
  one forward only**: any gateway edit beyond that is called out at its ticket consult.

## 4. Context-index architecture (must-pass)

- **CTX-1 (block) — the context source + confined root.** Migration **0014** (K1) adds
  `context_sources` (id, root_path, `scope_type`='workstream', `scope_id`, index/staleness metadata).
  Registration/list/remove are typed, CSRF-gated `human-agent` routes (`/v1/context-sources*`,
  owner-scoped). The file reader is **confined to the registered root** (K5, SEC-33): a test proves a
  `../` or out-of-root symlink is neither read nor indexed. Charter-bound is the only v0.10 scope.
- **CTX-2 (block) — the deterministic FTS index.** `context_chunks` (0014): source_id, locator
  (file + region/heading), a `tsvector` column with a GIN index. Source content is chunked (K2: by
  document/heading for docs + tickets; by file/region for code) and indexed; retrieval ranks by
  **`ts_rank` (lexical) + recency only**. **Native Postgres FTS — no new extension, no embeddings, no
  new dependency.**
- **CTX-3 (block) — the in-process incremental indexer.** A background indexer **rides the api's
  existing background goroutine** (the ticker/reaper precedent — no new unit/env/key; the `internal/*`
  extraction trigger stays unfired). Freshness is **incremental** (K6): the sweep compares each file's
  **mtime + size first and hashes only changed candidates** (no full re-hash per pass); each source
  carries a **staleness signal** surfaced to composer + operator. DB-indexed with an on-demand manifest
  render (the memory-context storage rule; never hidden-only).
- **CTX-4 (block) — the agent read plane.** A **separate** grant-scoped read method on
  `internal/context` (`SearchForAgent`) reuses the `ReadForAgent` CTE skeleton: live grants → the
  grant's charter (`workstreams.grant_id`) → context sources bound to that charter → FTS over their
  chunks; results clamped in-store (K4: default 50 / max 200). Served by a new internal api route
  (subject-pinned to `mcp-gateway`, typed `agent-workspace`), reached only via the gateway
  `context.search` tool.
- **Extraction stays deferred (pass).** The indexer + read ride gateway→api in-process; still no
  out-of-process consumer (the trigger is unfired).

## 5. Governance & consent (must-pass)

- **GOV-11 (block) — the context-source consent surface.** Registration copy states plainly: a bound
  context source's content becomes **readable by this charter's composer agent** (naming the
  prompt-injection risk honestly); removal stops future reads but cannot recall past ones. The
  always-park invariant is stated: a plan grounded in indexed content is still reviewed before
  execution. No dark patterns.
- **GOV-8/9/10 (block, carried).** The v0.8/v0.9 memory + charter + plan-preview consent copy is
  untouched.

---

## 6. Durability & lifecycle (must-pass)

- **CTX-5 (block) — indexer + source lifecycle.** Removing a context source (or retiring its charter)
  removes its chunks and stops its indexing; a crashed indexer self-heals on the next sweep (the
  mtime/hash state is derivable from disk + the durable index). No wedge: an unreadable/absent root
  marks the source **errored + stale** (surfaced) rather than crashing the sweep.
- **DUR-1..10 (block/pass, carried).** Run-engine claims/resume, the scheduler, the memory sweep, and
  the v0.9 cascade are untouched.

---

## 7. Audit & Evidence (must-pass)

- **AUD-21 (block) — the context-read vocabulary.** One new content-free event via the existing
  outboxes: **`context.read`** (agent plane only, one per `context.search` call: the query as metadata,
  the returned chunk ids, agent actor, the `agent-workspace` edge — never source content). Operator
  context-source management chains its own `human-agent` events (`context.source.registered` /
  `…removed`, content-free — exact names pinned at the ticket). Operator reads/searches (if any admin
  preview exists) stay unchained (the ADR-0064 §8 posture).
- **EVD-7 (pass) — context provenance.** From a terminal adaptive Run, the evidence trail resolves the
  `context.read` events beside the composition (which context informed the plan), alongside the v0.9
  `memory.read` trail — WD-10 §8 proves the round trip.

## 9. Offline install & operability (must-pass)

- **OI-17 (block).** Everything ships inside the existing binaries: one api migration (**0014**, K1)
  run by the existing `install.sh` migrate loop; the indexer rides the **existing api goroutine**; the
  `context.search` tool rides the **existing gateway binary and `/mcp` route** — **no new systemd unit,
  no new Caddy route, no new key material, no new required env**. (A context source's root is an
  operator-provided local path, registered at runtime — not install wiring.) A fresh installer-driven
  boot brings the stack `active` and the **full WD-10 passes installed** (K-installed, the production
  posture; **bundle rebuilt from HEAD before the run** — the t033 lesson); `task offline-bundle`'s size
  gate holds. No SaaS runtime dependency.

## 10. Performance & resource safety (must-pass)

- **PERF-11 (block) — the new-surface bounds.** **(1)** `context.search` results store-clamped (K4:
  50/200); **(2)** the query is length-bounded and the FTS uses the GIN index (no seq-scan on a large
  source); **(3)** the incremental sweep is mtime/size-gated (hashes only changed files) and batched so
  a large source cannot stall the shared goroutine; **(4)** per-source chunk count / total index size
  is bounded (a runaway source is capped + surfaced, not silently unbounded); **(5)** `context.search`
  rides the gateway's existing per-agent concurrency cap (the `memory.read` precedent).
- The v0.3–v0.9 floors (PERF-1..10) are unchanged.

## 13. ADR dependencies

- **ADR-0066 — Layer 1 Live/Context Index (Accepted 2026-07-23).** The sole new ADR. Settles: the
  operator-registered charter-bound context source (R1); the reserved `agent-workspace` edge enforced
  on the read path (R2, the set unchanged); native Postgres FTS with zero new dependency and
  tree-sitter deferred-with-a-recorded-trigger (R3); the `context.search` tool on the `memory.read`
  forward pattern with grant-scoped containment, per-read chaining (SEC-33), and the confined in-process
  indexer (R4). The consult decisions K1–K5 are criteria-level value picks within the ADR's stated
  intent (the v0.6–v0.9 precedent). Any divergence surfaced at a ticket consult files a new ADR.

## 14. Deferred (with promotion triggers)

- **tree-sitter AST / code-graph retrieval** — deferred (native FTS suffices for a composer that plans
  shell commands, not code edits; keeps the zero-new-dependency posture). **RECORDED TRIGGER (CEO R3
  note): when agents gain a code-EDITING capability** — code-structure retrieval (call graphs, symbol
  resolution, blast-radius) becomes valuable — add tree-sitter AST indexing, most naturally alongside
  **Git Intelligence (REQ-015)**. A *when*, not an *if*.
- **The `agent-repo` edge** — held reserved for Git Intelligence (REQ-015).
- **Remote-target indexing** (content on a remote resource vs. a local source) — needs governed egress;
  deferred.
- **Operator-shared / run-scoped context sources** — v0.10 is charter-bound only (tightest
  containment); broader scopes defer.
- **Learned ranking / computed `confidence`** (L3), **messages/chat indexing** (no chat corpus),
  **multi-source federation** — deferred.
- **Layer 3 — Reasoning Retrieval** — **hard-gated** (any embedding/AI dependency = its own ADR
  against the offline + no-SaaS doctrine).
- **The `internal/*` extraction; cron; DAG; the gateway exec worker; SSH pooling; full rate-limiting;
  TR-2** — unchanged prior deferrals.
- **QR pairing + mobile approval; the Slack/mobile integration connector; GUI (RDP/VNC) + browser
  computer-use cockpit modalities** — the Beta-1 UX track + post-Beta modality ADRs (separate from L1;
  recorded at the v1.0-candidate scan).
