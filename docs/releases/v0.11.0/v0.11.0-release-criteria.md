# v0.11.0 — Release Criteria

Status: **Accepted — 2026-07-26** (v0.11 "Operator Experience" scoping consult; the nine decision
points D1–D9 that this document implements were CEO-ratified on the war-room recommendation). The
single architecture ADR it depends on (**ADR-0067 — Audit read semantics**) is **Accepted**;
acceptance of *this* document fixes the release intent. Future changes to this document require a
new ADR (criteria drift is a load-bearing decision — the v0.1.0–v0.10.0 rule).

Owner: War Room Commander (synthesis); Audit/Evidence Reviewer (EVD-8, the reverse cursor, the
preset, the disclosure envelope); Frontend Lead (the audit view, the detail polling); Knowledge/Context
Architect (the charter-scope read resolution); Permission Model Reviewer (the no-new-capability
assertion and the WD-9 containment re-proof).

This document defines what shipping **v0.11.0 — "Operator Experience"** means. Every criterion is
*pass* (must be true), *block* (presence stops release), or *deferred* (explicitly out of scope, with
the trigger that promotes it back). The criteria are the exit gate for every v0.11.0 ticket: a ticket
is "done" when it closes one or more criteria here and breaks none.

---

## 1. Scope of v0.11.0

v0.11.0 is the **first of the three-release Beta-1 path** ratified 2026-07-24
(`docs/requirements/epic_story_catalog_v4.md` §Part 4): **v0.11 Operator Experience → v0.12 Access &
Onboarding → v1.0 MVP Beta 1**. It fixes **defects on already-shipped functionality** and adds no new
governed capability — deliberately, because the release that follows it adds surfaces and the one
after that freezes the API.

It delivers three epics:

- **E-01 — Audit read surface (REQ-003, B-014, gap G2) — v1.0-BLOCKING.** The audit trail **is** the
  product's core evidence claim. Measured live at the §human WD-10: **635 events, 601 (95%)
  adaptive-charter lifecycle noise, the newest entries 13 "next page" clicks deep.** Reverse cursor +
  newest-first default + server-side filtering + a versioned read-time noise preset, all under the
  **EVD-8 chain-contiguity invariant** (ADR-0067 §D1).
- **E-07 — Live detail refresh (REQ-007, B-019, gap G6).** Targeted, panel-scoped polling of the
  charter-detail lists so a live charter stops reading as stale.
- **E-08 — Charter-scope accrual (REQ-014, B-029).** The charter-detail memory read resolves
  run-scoped accruals bound to the charter's grant, closing the inversion where **the operator sees
  less than the composer does**.

**Hard constraint (the release's defining posture).** v0.11.0 adds **no capability, edge, actor,
grant, token, credential, consent moment, egress path, migration, service, unit, env var, key, or
third-party dependency — and no write path of any kind.** The `audit-service` append side is
**byte-untouched**: `chain.Compute`'s input domain is unchanged, no event's vocabulary changes, and
the only migration is a **read-only index migration** (0002 — three composite indexes, no column, no
constraint, no trigger; PERF-7). Every change is on a read path already gated by an existing
capability check.

**Out of scope** (→ §14): the upstream re-ask backoff (it would change governed lifecycle behavior and
mint a WD); SSE/event push; per-column sorting on non-`seq` columns (rejected, not deferred);
backfilling existing run-scoped accruals (rejected); full-text/target search, time-range filters,
saved views, export; in-browser page chain verification.

The wedge is **an operator who opens `/audit` on a production-volume stack and finds the most recent
governed action on the first screen, with no paging — and can always reach the complete, contiguous,
verifiable chain in one interaction.**

## 2. The gate — no new WD (structural rule #2, re-tested)

**v0.11.0 mints no new walkthrough demo.** Under the ratified structural rule — *a new WD-N is minted
**only** when a release adds new governed capability, not once per release out of habit* — none of the
three epics qualifies. This was **re-tested against the as-built at the scoping consult, not
inherited** (ADR-0067 §D8):

| Epic | New governed capability? | |
|---|---|---|
| E-01 | New query params on an existing operator GET already gated by `operatorSubject`. No new edge, actor, grant, token, or consent moment. | **No** |
| E-07 | Polling an existing GET more often. Operator read routes chain nothing. | **No** |
| E-08 | Memory scope **is** a containment boundary, so this got a real look — but both `run:<id>` and `workstream:<id>` for an adaptive Run resolve to the **same grant**. The label moves; the visible set does not. | **No** |

**The gate is therefore:**

- **GATE-1 — Full WD regression.** **WD-1 … WD-10 all green** on the Dockerized compose stack
  (`task e2e`) and on the **installed** privileged-systemd stack (`task wd1`). The audit chain verifies
  intact end-to-end. **WD-9's N1 and N3 cross-grant negatives are named explicitly** as the E-08
  containment re-proof.
- **GATE-2 — Browser smoke green** (`task smoke`, all cases), including the new audit-view assertions
  (§8).
- **GATE-3 — CEO §human spot-check.** Driven live in a **real host browser** (Chrome/Edge at
  `http://localhost:5173` via the ADR-0047 dev proxy — the Windows-host TLS route recorded in the
  v0.9.0/v0.10.0 runbook Step 6), covering the four operator-visible behaviors:
  1. `/audit` opens newest-first, and the most recent governed action is on the **first screen with no
     paging**, on a stack carrying production-shaped lifecycle volume.
  2. The preset is **disclosed** — the operator can see they are on a filtered view, can see the total
     chain length, and reaches the **complete unfiltered chain in one interaction**.
  3. A server-side filter (actor / outcome / edge) returns matches **from the whole chain**, not from
     the loaded page — demonstrated by filtering to a value whose matches are deep in the chain.
  4. An open charter-detail panel **refreshes itself** as the charter ticks, and stops when the panel
     closes or the tab is hidden.

**Regression posture.** WD-1..WD-10 are *all* elevated this release: v0.11 touches a surface every
prior wedge's evidence leg reads through, so any silent regression in the audit read path would be a
regression in every gate the product has.

## 3. Audit read semantics (must-pass) — the EVD block

- **EVD-8 (the invariant).** A view that is not a **contiguous, `seq`-ordered window** over the chain
  is presented as a **query result**, never as a chain segment; it discloses that it is filtered and
  the size of the chain it was drawn from. The unfiltered `seq`-ordered timeline remains the canonical
  evidence view and is reachable in **one interaction**. *(ADR-0067 §D1)*
- **EVD-9.** Every event remains **chained, stored, and returned by the unfiltered API path** exactly
  as before this release. **No event is ever unretrievable**, and **no rendered row is ever a row that
  is not a stored event** (no rollups, no synthesized rows).
- **EVD-10.** No schema change that alters **stored data**, the **chain input domain**
  (`chain.Compute`), or any event's actor/edge/target/outcome **vocabulary**. A **read-only index
  migration is the only permitted migration category**, and it must add no column, constraint, or
  trigger. *(block if violated)*

  > **Amended 2026-07-26 at the T-105 consult** (one commit after acceptance, before any code
  > existed). As first written this criterion banned *all* `audit-service` migrations, which
  > contradicted PERF-7: `audit_events` carries no index on `actor`/`edge`/`outcome`, so a selective
  > filter would degrade to a full scan. The criterion's *intent* was always "do not touch stored
  > data or the chain input" — a `CREATE INDEX` satisfies that intent exactly (it changes no row, no
  > hash input, and is DDL the append-only trigger does not gate). The drift rule binds normally
  > from T-105 onward.
- **EVD-11.** The lifecycle-noise policy is a **read-time predicate**, never write-side suppression,
  never a rollup, never a stored column. *(block if violated — ADR-0067 §D3 rejected all three)*

## 4. Audit read surface — mechanism (must-pass)

- **AUD-22 — Reverse cursor.** `audit-service`'s store gains a descending keyset path
  (`WHERE seq < $1 ORDER BY seq DESC LIMIT $2`) alongside the existing ascending one, selected by an
  explicit direction parameter. Both directions are **contiguous** and remain chain segments.
- **AUD-23 — Keyset stability, proven live.** A live test proves that paging in **both** directions
  **skips no event and duplicates none**, including **across a concurrent append** landing mid-page.
  Offset pagination is not used anywhere on this surface.
- **AUD-24 — Newest-first default.** The operator surface defaults to descending. The ascending path
  is preserved and reachable (chain-order reading remains possible).
- **AUD-25 — Server-side filtering.** Equality predicates on **actor**, **outcome**, and **edge**, each
  applied **before** the `LIMIT` and composable with the cursor and direction. A live test proves a
  filtered read returns matches **from the whole chain**, including matches beyond the first page's
  worth of unfiltered events.
- **AUD-26 — Client-side filtering stays forbidden.** The v0.1.0 rule stands unamended; no filtering
  or re-sorting of a fetched page happens in the browser. `Audit.tsx`'s header comment is updated to
  record why the rule stands and what now supersedes its scope. *(block if violated)*
- **AUD-27 — Ordering is seq-direction only.** No sort parameter exists for `timestamp`, `actor`,
  `edge`, `outcome`, or any other column. *(`timestamp` is producer-supplied through the outbox; only
  `seq` is authority-assigned and defines the chain — ADR-0067 §D2)*
- **AUD-28 — The preset.** `audit-service` owns exactly one named, versioned preset,
  **`governed-actions@1`**, whose excluded outcome set is **exactly `{plan.requested, plan.expired}`**
  — content-free charter-lifecycle facts only. Its membership is defined in **one** place in
  `audit-service` (not in the frontend, not in the database, and **not in a migration**) and is
  enumerated here; widening it is a criteria change and therefore requires a new ADR.
- **AUD-29 — Disclosure envelope.** The page response carries the applied preset/filter state and
  **`chainHead`** — `MAX(seq)`, the newest chain position — computed in O(1) (**not** a complement
  count, **not** `COUNT(*)`). `nextCursor` semantics are preserved verbatim — emitted only when a
  full page came back.

  > **Amended 2026-07-26 at the T-105 consult** (rename + semantics, same quantity). ADR-0067 §D5
  > decided "O(1), from `MAX(seq)`, never a complement count" — that decision is **unchanged**. The
  > field was named `chainLength`, which **misdescribes** the quantity: `seq` is `BIGSERIAL` and
  > `nextval` is non-transactional, so a rolled-back `Append` burns a value and leaves a gap —
  > `MAX(seq)` therefore **overstates** the row count. Reporting it as "the chain has N events" would
  > be a dishonest disclosure number in the one criterion whose whole purpose is honest disclosure.
  > `chainHead` is exact, O(1), and semantically precise. Consistent with as-built: `audit-service
  > verify` already walks ordered position rather than `seq` contiguity, so gaps are an accepted
  > property of the chain.
- **AUD-31 — The preset must not swallow NULL outcomes.** `outcome` is **nullable** (inserted as
  `NULLIF($7,'')`, read as `COALESCE(outcome,'')`), and in SQL `outcome NOT IN (…)` evaluates to
  **NULL** — not true — for a NULL outcome, which would **silently exclude every event that has no
  outcome** from the default view. The predicate is written NULL-safe
  (`COALESCE(outcome,'') <> ALL(…)`), and a live test asserts that a **NULL-outcome event appears
  under the preset**. *(block if violated — this is the "evidence hidden by a default" failure mode
  ADR-0067 exists to prevent, arriving through three-valued logic rather than through a decision.)*
- **AUD-30 — Proxy posture preserved.** `services/api`'s `ListAuditEvents` forwards the new params and
  keeps its existing posture **byte-identical**: the operator is gated by the shared capability
  middleware, and api reads `audit-service` with its **own service token**, so the chain authority's
  write gate never accepts an operator token. *(block if violated)*

## 5. Contract & codegen (must-pass)

- **VER-2 — Zero codegen drift.** `task codegen` is byte-deterministic (prove: copy, re-run, diff
  empty) across `services/{api,audit-service}/internal/server/gen.go` and
  `packages/shared-types/src/generated/openapi.ts`.
- **CON-1 — Fragment discipline.** The new parameters are **new named components** referenced by
  `/v1/events` and `/v1/audit/events` **only**. **`LimitParam` and `CursorParam` are not edited** —
  they are shared by resources, runs, grants and every other list route, and editing them would
  silently change every list surface in the product. *(block if violated — ADR-0067 §D9)*
- **CON-2 — Additive only.** No existing operation, parameter, schema, or response shape is removed or
  narrowed. This is the last substantial growth of the audit surface before the E-06 freeze.

## 6. Live detail refresh (must-pass)

- **FE-27 — Targeted polling.** The charter-detail reads (detail / plan requests / context sources /
  scoped memory / runs) poll on a fixed short interval **only while the detail panel is open**.
- **FE-28 — Bounded and self-limiting.** Polling stops when the panel closes, when the charter is not
  `active` (paused / retired / closed), and when `document.visibilityState === "hidden"`. An
  unattended cockpit left open overnight does not poll until morning.
- **FE-29 — Freshness is visible.** The panel surfaces an "updated Xs ago" affordance, so the operator
  can tell live from stale rather than inferring it.
- **FE-30 — Polling chains nothing.** A live assertion confirms that an open, polling detail panel adds
  **zero** audit events over its lifetime. *(Operator read routes are bare `SELECT`s; the chained
  `memory.read`/`context.read` events are on the agent planes only. This criterion exists because a
  regression here would feed the exact noise E-01 fixes.)*

## 7. Charter-scope accrual (must-pass)

- **MEM-9 — Read-side resolution.** The charter-detail memory read resolves the charter's scope to
  include **run-scoped rows for Runs bound to that charter's grant** — the same CTE shape
  `ReadForAgent` already uses.
- **MEM-10 — Derivation unchanged.** `scopeForActor` and ADR-0064 §1/MEM-2 are **byte-unchanged**; no
  accrual writes to a different scope than it does today. *(block if violated)*
- **MEM-11 — No backfill, no migration.** No existing `memories` row's `scope_type`/`scope_id` is
  rewritten. *(A rewrite would make the row disagree with its own already-chained `memory.written`
  event — ADR-0067 §D7.)* *(block if violated)*
- **MEM-12 — Containment re-proved.** WD-9's **N1** and **N3** cross-grant negatives stay green: the
  widened read reaches only rows whose Run is bound to **this** charter's grant, and a foreign
  charter's accruals remain unreachable. The operator memory surface `/v1/memories*` gains no new
  cross-scope read beyond this resolution.
- **MEM-13 — The inversion closes.** A live assertion shows an adaptive charter's completed Run's
  accrued pointer **appearing in the charter-detail widget**, where today it does not — for a Run
  accrued **before** this release as well as after (the read-side fix covers history).

## 8. Frontend (must-pass)

- **FE-31 — Newest-first, one screen.** `/audit` opens newest-first on the preset; the most recent
  governed action is visible without paging.
- **FE-32 — Honest disclosure.** The filtered state, the preset name, and the total chain length are
  visible in the view — never implied, never silent. "Show all events" is **one interaction** and
  returns the contiguous unfiltered timeline. *(EVD-8)*
- **FE-33 — Filters are server-side.** The actor/outcome/edge controls issue new requests; nothing is
  filtered or re-sorted in the browser. *(AUD-26)*
- **FE-34 — Browser-rendered evidence.** Per the project DoD, changes to `apps/web` rendering output
  ship with browser-rendered evidence (a screenshot or a passing Playwright assertion against the
  rendered DOM). **jsdom unit tests do not satisfy this.** Vitest coverage is additionally expected
  for the new `Audit.tsx` and `Workstreams.tsx` logic.
- **FE-35 — Design-system preflight.** No ad-hoc component; existing tokens/components/variants and
  accessibility rules are identified before any new UI is written
  (`../agency-kit/ai/core/design-system-governance.md`).

## 10. Performance & resource safety (must-pass)

- **PERF-6 — The descending path is index-backed.** Both directions are keyset reads on the `seq`
  primary key; neither introduces a sequential scan on the audit table.
- **PERF-7 — Every filter dimension is index-backed.** Migration **0002** adds three composite
  indexes — **`(actor, seq DESC)`, `(outcome, seq DESC)`, `(edge, seq DESC)`** — so no filter the
  operator can choose falls off a performance cliff. *(Index-only; no column, constraint, or trigger
  — permitted by the amended EVD-10.)*

  **Rationale (settled analytically at the T-105 consult, not deferred to measurement).** A selective
  equality filter with `ORDER BY seq DESC LIMIT n` is the textbook composite-index case: unindexed,
  `actor = '<rare>'` walks the entire PK index backwards and never satisfies the LIMIT. **All three
  dimensions are indexed, not just `actor`,** because low cardinality does not imply density *per
  value* — `edge = 'agent-repo'` currently matches **zero** rows (a reserved edge), so unindexed it
  full-scans to return nothing. Write cost is negligible *here specifically*: appends already
  serialize on `pg_advisory_xact_lock` with a chain-tail round-trip, against which three btree
  inserts disappear. **Predictable performance is a quality property of an evidence surface** — one
  that is fast for some filters and seconds for others is a bad one.
- **PERF-8 — The default preset path needs no index, and its cost is bounded.** `outcome`-exclusion
  is a backward PK walk with a filter, touching ≈ `limit ÷ (1 − noiseRatio)` tuples (~1,000 at the
  measured 95%) — **bounded by the LIMIT and the ratio, never by table size.** *(Recorded escalation,
  §14: if the ratio ever exceeds ~99%, revisit — a partial index is the structural answer and was
  rejected here for coupling the lens to the schema.)*
- **PERF-9 — `chainHead` is O(1).** `MAX(seq)` on the primary key; never a complement count,
  `COUNT(*)`, or a full aggregate.
- **PERF-10 — Plans verified, not assumed.** The measurement on a seeded production-shaped chain is a
  **verification** step: `EXPLAIN` shows `Index Scan` (never `Seq Scan`) for the unfiltered,
  preset, and each single-dimension filtered read.
- **PERF-11 — Polling is bounded.** One open panel only; the interval is fixed and does not compound
  with the number of charters, runs, or open browser tabs.

## 15. Ticket ladder (indicative; each JIT-authored with its own consult)

**Ordering constraint (found at the T-105 consult).** `audit-service`'s `ListEvents` handler takes
`ListEventsParams` — **generated** from the fragment by `task codegen`. New query parameters therefore
cannot reach the handler until the fragment carries them, so the store layer (T-105) and the contract
+ its two consumers (T-106) must be cut in that order. This mirrors the established
data-layer-then-frame split (T-058a → T-058b, T-055's seam extraction).

| Ticket | Scope | Closes |
|---|---|---|
| **opener** | ADR-0067 + these criteria (docs-only) | DOC-18 |
| **T-105** | `audit-service` **store layer only** — `ListQuery` (direction, filters, preset, `chainHead`), migration 0002 (index-only), live PG tests. Call sites stay behavior-preserving; **no generated code touched** | EVD-8..11, AUD-22..23, AUD-25, AUD-27..29, AUD-31, PERF-6..10 |
| **T-106** | The contract and both consumers as one unit: OpenAPI fragment (new named components) → codegen → `audit-service` handler → api proxy forwarding | VER-2, CON-1, CON-2, AUD-24, AUD-30 |
| **T-107** | `Audit.tsx`: newest-first, direction toggle, server-side filters, preset + disclosure banner; browser-rendered evidence | AUD-26, FE-31..35 |
| **T-108** | E-07 targeted panel polling (active-only, visibility-paused, freshness affordance) | FE-27..30, PERF-11 |
| **T-109** | E-08 read-side charter-scope resolution | MEM-9..13 |
| **T-110** | Closure: WD-1..10 regression (compose + installed), smoke, OI-18..20, docs, §human spot-check, artifacts, tag `v0.11.0` | GATE-1..3, DOC-19..22, VER-6..9 |
