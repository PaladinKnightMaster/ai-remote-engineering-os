# v0.9.0 — Release Criteria

Status: **Accepted — 2026-07-16** (v0.9 criteria consult; the five consult decisions
C1–C5 — deny-is-canceled-plus-`run.denied`, plan-request-TTL-equals-interval, the
Run-plane approval surface, the single migration 0013, and the v0.8 read-clamp with the
full installed WD-9 scope — were CEO-ratified, and the three code-grounding findings
F-a (the `runs_status_chk` alter + `proposed`-inertness), F-b (WD-8's exact-set
`tools/list` assertion must be amended when the catalog grows), and F-c (the
`LaunchBounded` third caller needs a behavior-preserving disposition split) are baked in
below). The single architecture ADR it depends on (**ADR-0065 — Adaptive Workstreams**)
is already **Accepted** (`80de0dc`); acceptance of *this* document fixes the release
intent. Future changes to this document require a new ADR (criteria drift is a
load-bearing decision — the same rule as v0.1.0–v0.8.0).

Owner: War Room Commander (synthesis); Workstream Architect (the adaptive kind + the
plan-request channel + the `proposed` Run); Permission Model Reviewer (SEC-32 — the
lit `agent-memory` edge, same-grant containment, the share flip); MCP Gateway Reviewer
(the three control-plane tools — the gateway stays keyless); Audit/Evidence Reviewer
(the per-read chaining + the plan-lifecycle vocabulary); Offline-Install Engineer
(OI-16 — an api migration only; the new tools ride the existing gateway binary).

This document defines what shipping **v0.9.0 — "Adaptive Workstreams" (governed agent
memory access + agent-composed plans — the loop closes: remember → plan → govern → act
→ accrue)** means. Every criterion is *pass* (must be true), *block* (presence stops
release), or *deferred* (explicitly out of scope, with the trigger that promotes it
back). The criteria are the exit gate for every v0.9.0 ticket: a ticket is "done" when
it closes one or more criteria here and breaks none.

---

## 1. Scope of v0.9.0

v0.9.0 discharges ADR-0064 §Deferred's **fused pair** — `agent-memory` enforcement and
memory→execution coupling ("one trigger, together or not at all") — and ADR-0063
§Deferred's agent-composed-plans item, under the consent + containment model both
recorded as their gate (**ADR-0065**). It is the release where the v0.8 memory store
**feeds execution under governance** for the first time.

**Doctrine posture (settled at the scoping consult).** The plan author is the
**customer's external agent, inbound over the ADR-0056 MCP surface** — the platform
ships no model, embeds no AI, dials nothing out; v0.6 agents already compose per-launch
plans (`run.launch`, plan ⊆ grant), and v0.9 adds only the *standing* per-tick form.
The L3 hard gate (any embedding/AI dependency = its own ADR) is untouched.

**Hard constraint (preserved).** Nothing new mints; the gateway stays **keyless**
(ADR-0060); the broker remains the sole SSH egress; **no new key, no new credential
custody, no new egress path, no new token-minting workload**. The gateway diff is
real this release but **bounded to the catalog + forwards** (three control-plane tools
on the `run.launch` pattern); the operator memory surface (`/v1/memories*`) is
**byte-identical to v0.8** — the agent plane is a separate, read-only, grant-scoped
path.

Concretely, on top of the v0.5–v0.8 platform, v0.9.0 delivers:

- **The agent memory-read plane** — the gateway `memory.read` tool → pinned api
  forward, typed with the newly **enforced `agent-memory` edge**; read-only,
  same-grant-scoped **by construction**, share-gated for authored content, per-read
  chained.
- **The adaptive charter kind** — additive `kind` on `workstreams`: objective + bounds
  + schedule + a **named composer agent** (= the auto-issued grant's grantee, R2) and
  no template steps; `template` charters are structurally untouched.
- **The inbound plan channel** — a tick opens a durable, TTL-bounded **plan request**;
  the composer discovers it (`workstream.poll`) and answers it (`plan.submit`); the
  platform initiates nothing outbound.
- **The plan-preview park** — a submitted plan is validated plan ⊆ grant, then created
  as a **`proposed` Run** parked for informed full-plan review; approve → `pending` →
  the existing sequencer; deny → terminal (C1). **Adaptive plans always park at v0.9.**

**Out of scope** (→ §14): agent memory **writes**; unattended adaptive execution;
Layer 1 (Context Index); Layer 3 (hard-gated); computed confidence; retention default;
multi-operator ACL; manifest-primary storage.

The wedge is **one platform where a real external agent reads governed memory it is
entitled to, composes the next tick's plan from it, a human reviews that exact plan
before anything runs, the governed engine executes it, the outcome accrues — and the
next tick's read provably sees what the last tick learned** (WD-9). Everything else
exists to make that true and verifiable.

## 2. WD-9 — the single load-bearing wedge (the demo)

**WD-9.** On a real (not mocked) stack, the loop closes under governance. WD-9
comprises a **happy path** (1–8) plus six independent **live negatives**:

1. **An adaptive charter is consented in one act.** The operator charters an
   `adaptive` Workstream — objective + resource/verb scope + schedule + bounds + the
   **named composer agent** — with the GOV-10 consent copy in frame; the auto-issued
   grant's grantee = the composer (R2); `workstream.chartered` + `grant.issued` chain
   as one consent act.
2. **The tick publishes, nobody composes yet.** The ticker's adaptive branch opens a
   durable plan request (TTL = the interval, C2); `plan.requested` chains; the charter
   template path is not involved.
3. **The agent reads its memory — chained.** The composer (a real MCP client with a
   valid `aud=mcp-gateway` Bearer) calls `memory.read`: it receives the charter's
   accrued reference rows (content-free) and any **shared** authored rows — and one
   content-free **`memory.read`** event chains per call (row ids, agent actor, grant).
4. **The agent composes and submits.** `workstream.poll` shows its open request;
   `plan.submit` (idempotency-keyed on the tick launch key) passes plan ⊆ grant
   (SEC-29, the shared `LaunchBounded` core — F-c) and creates a Run in status
   **`proposed`**; `plan.submitted` chains. The `proposed` Run is **inert** (F-a): the
   sequencer does not claim it, the reaper does not orphan it, cancel guards ignore it.
5. **A human reviews the exact plan.** The operator opens the preview (the `/runs` +
   workstream-detail surface, C3): every step's resource + sealed command is visible —
   the consent successor invariant rendered (consent binds to *this tick's reviewed
   plan*). Approve (`POST /v1/runs/{id}/approve`, cookie + CSRF) → `pending`.
6. **The existing engine drives it.** The sequencer executes the approved plan
   unchanged — actor = the composing agent, principal = the operator; flagged
   resources would still park per step in addition.
7. **Terminal accrues — and the loop closes.** The Run reaches terminal and accrues
   its content-free pointer (the v0.8 machinery unchanged); **the next tick's
   `memory.read` returns the new row** — the agent's plan-time context provably
   contains what the last tick learned.
8. **The chain proves it.** `audit-service verify` — intact; the full loop is present
   and content-free: `plan.requested` → `memory.read` → `plan.submitted` → the
   `proposed`-Run resolution → `run.*` lifecycle → `memory.written`.

**Live negatives (all live in the gate):**

- **N1 — cross-grant containment (the SEC-32 negative).** A second grant/charter with
  its own memory exists; the composer's `memory.read` **cannot** return any row of the
  foreign scope or any `operator`-scoped row — and the attempt is visible (the read
  event lists only same-grant rows; a request naming a foreign scope is refused).
- **N2 — the share gate.** An operator-authored row is invisible to `memory.read`
  until `memory.shared` flips it (event chained exactly once); after
  `memory.unshared`, it is invisible again — the flip pair is idempotent (no duplicate
  events on re-flips).
- **N3 — revocation kills all three surfaces.** After grant revoke:
  `workstream.poll`/`plan.submit`/`memory.read` are refused; an open plan request is
  closed; a `proposed` Run of the dead grant **cannot be approved** into `pending`.
- **N4 — expiry never wedges.** An unanswered plan request expires at its TTL
  (`plan.expired` chained); the next tick opens a fresh request; the charter stays
  healthy.
- **N5 — plan ⊆ grant holds unchanged.** A submitted plan naming an out-of-grant
  resource is refused (the SEC-29 refusal, chained) and creates no Run.
- **N6 — the tool surface is exact (F-b, the WD-8 N2 amendment).** `tools/list`
  exposes exactly `{remote.exec, run.launch, workstream.poll, plan.submit,
  memory.read}` — and **no memory-write tool of any kind**; the WD-8 assertion is
  amended to this set with its spirit intact.

**Regression guards (elevated this release).** **WD-5 + WD-6 + WD-7 + WD-8 all stay
green**: F-c touches the shared launch core (WD-6/7 prove the existing two callers are
behavior-preserved), F-a touches the Run-status universe (WD-5 proves the driver), and
the operator memory surface must stay byte-identical (WD-8 proves it, with its N6/F-b
tool-set amendment). The chain stays intact end-to-end.

**This demo (happy path + N1–N6) is the release gate** — built as an extension of the
`tests/e2e` live harness and re-run (full scope, C5) on the installer-produced stack.

## 3. Capability-edge security (must-pass)

Every boundary stays gated by `packages/go/middleware` `RequireCapability`. v0.9.0
**enforces the reserved `agent-memory` edge on exactly one path** (the memory-read
tool + its pinned forward) — the canonical edge *set* is unchanged (ADR-0046
preserved); `workstream.poll`/`plan.submit` ride the existing `agent-tool` reading.

- **SEC-32 (block) — the adaptive invariant (the release's named invariant).** Agent
  memory access is **read-only** (no agent write path exists; reference accrual on the
  terminal flip remains the sole machine write); the readable set derives from **the
  caller's own grant by construction** (its charter's `workstream:<id>` scope + that
  grant's Runs via `runs.grant_id` — never `operator` scope, never a foreign charter);
  operator-authored content is **share-gated** (`agent_visible` default false; the
  audited flip pair); **every agent-plane read is chained** (`memory.read`,
  content-free); and **every agent-composed plan parks** as a `proposed` Run before
  any step executes (unattended-adaptive does not exist at v0.9, not even as
  configuration). N1/N2/N6 are its live negatives; the operator `/v1/memories*`
  surface is byte-identical to v0.8 (a **separate** store method serves the agent
  plane).
- **SEC-29/30 (block, carried + extended).** Plan ⊆ grant is unchanged and now guards
  the third caller through the same shared core (F-c: **one validator, three
  callers**; the split is behavior-preserving for the existing two — WD-6/7 elevated).
  `plan.submit` additionally **pins the Bearer subject to the grant's grantee** (a
  foreign agent cannot answer another charter's request).
- **SEC-20/21/25/26..28/31 (block, carried).** The gateway stays keyless — every new
  verb is a forward minted with the gateway's own service token to subject-pinned api
  routes (the `run.launch` pattern); no foreign-edge mint; no gateway decrypt path;
  broker/connector pins unchanged; SEC-31's operator-plane clauses carry (amended
  only as ADR-0065 records — the read-only agent exception this document names
  SEC-32). The gateway diff is **catalog + forwards only**: any gateway edit beyond
  that must be called out at its ticket consult.

## 4. Adaptive architecture (must-pass)

- **MEM-5 (block) — the agent read plane.** A **separate** grant-scoped read method on
  `internal/memory` (the owner-keyed `List/Get` are untouched): input = the validated
  grant; the SQL derives the readable set from the grant's charter scope + its Runs;
  rows filtered to (accrued reference rows) ∪ (authored rows with `agent_visible`);
  sealed content is opened only for shared rows. Served by a new internal api route
  (subject-pinned to `mcp-gateway`, typed `agent-memory`), reached only via the
  gateway `memory.read` tool. Read results are clamped in-store (C5: default 50 /
  max 200, id-ASC — the v0.8 clamp).
- **MEM-6 (block) — the share flip.** Migration **0013** (C4) adds
  `memories.agent_visible BOOLEAN NOT NULL DEFAULT false`; `POST
  /v1/memories/{id}/share` + `…/unshare` (`human-agent` + CSRF, owner-scoped) as
  idempotent once-only flips chaining `memory.shared`/`memory.unshared` (the
  `flip()` precedent — re-flips are silent no-ops, no duplicate events). A redacted
  or expired row cannot be shared.
- **WS-5 (block) — the adaptive kind.** `workstreams` gains `kind`
  (`template`|`adaptive`; existing rows backfilled `template`) + the composer subject
  (0013). An adaptive charter carries **zero** `workstream_steps` rows and a named
  composer; chartering auto-issues its grant with **grantee = the composer** (R2) in
  the same transaction (the ADR-0063 consent act, now covering *who composes*).
  Template charters: schema, ticker path, and semantics **unchanged**.
- **PLAN-1 (block) — the plan-request lifecycle.** A `plan_requests` table (0013):
  charter-scoped, keyed by the tick launch key, TTL = the charter's interval (C2 — at
  most one open request per charter by construction; no new env). The ticker's
  adaptive branch opens it (`plan.requested`); `workstream.poll` lists the caller's
  own open requests; expiry closes it (`plan.expired`) and **never wedges** the
  charter; missed ticks collapse.
- **RUN-6 (block) — the `proposed` Run (F-a).** Migration 0013 alters
  `runs_status_chk` to admit `proposed`. `plan.submit` → the shared `LaunchBounded`
  core (F-c: a disposition parameter/variant; the existing two callers are
  byte-behavior-preserved) → a `proposed` Run (actor = the composer, principal = the
  operator, grant-linked). A `proposed` Run is **inert**: not claimable by the
  sequencer, not reapable as an orphan, ignored by cancel-in-flight guards — each
  status consumer explicitly audited at the ticket. `POST /v1/runs/{id}/approve` →
  `pending` (the sequencer takes over unchanged); `POST /v1/runs/{id}/deny` →
  terminal **`canceled` + a distinct chained `run.denied` event** (C1 — no new
  terminal status; the v0.8 accrual semantics apply verbatim, so a denied plan
  accrues exactly once as a canceled Run). Approve/deny are `human-agent` + CSRF,
  owner = principal (C3).
- **Extraction stays deferred (pass).** Every new path rides gateway→api in-process;
  still no out-of-process consumer (the trigger is unfired).

## 5. Governance & consent (must-pass)

- **GOV-10 (block) — the two consent surfaces.** **(1) The share flip's copy** states
  plainly: sharing places this row's content inside the composer agent's context
  (naming the prompt-injection/exfiltration risk honestly); unshare stops future
  reads but cannot recall past ones. **(2) The plan preview** renders the full
  composed plan (every resource + command) before approval — the consent successor
  invariant stated in the UI: for adaptive charters, consent binds to *each tick's
  reviewed plan* inside the standing grant's bounds. No dark patterns; deny is a
  first-class, always-visible action.
- **GOV-8/9 (block, carried).** Charter consent copy (now including the composer for
  adaptive charters) and the memory consent copy carry; the R2 forgetting boundary
  statements are unchanged.
- **GOV-5/6/7 (block/pass, carried).** Parking, delegated approval context, and
  owner-scoping are untouched.

## 6. Durability & lifecycle (must-pass)

- **DUR-10 (block) — the cascade re-aim + channel durability.** Grant
  revocation/expiry **closes open plan requests, refuses `plan.submit` and
  `memory.read`, and blocks `proposed`→`pending` approval** (N3) — the existing
  ADR-0062 cascade extended, no new machinery. Plan-request expiry is exactly-once
  (a status flip, the tombstone-guard pattern); a crashed ticker self-heals on the
  next tick (the request TTL and `next_fire_at` are both durable); `proposed` Runs
  survive restarts inert (F-a).
- **DUR-1..9 (block/pass, carried).** Run-engine claims/resume, scheduler
  durability, and the memory sweep are untouched.

## 7. Audit & Evidence (must-pass)

- **AUD-20 (block) — the loop vocabulary.** New content-free events via the existing
  outboxes: **`memory.read`** (agent plane only, one per tool call: row ids, agent
  actor, grant — never content), **`memory.shared`** / **`memory.unshared`**
  (operator flips, in-tx with the row), **`plan.requested`** / **`plan.submitted`**
  / **`plan.expired`** (the request's transaction), and **`run.denied`** (C1, beside
  the terminal event). Operator memory reads stay unchained (the ADR-0064 §8
  posture — the escalation fired for the non-owner plane only).
- **EVD-6 (pass) — loop provenance.** From a terminal adaptive Run, the evidence
  trail resolves the whole tick: the plan request, the `memory.read` events beside
  the composition, the reviewed plan (the Run's sealed steps), the approval, the
  step evidence, and the accrued pointer — WD-9 §8 proves the round trip.

## 14. Deferred (with promotion triggers)

- **Agent memory writes** (agent-authored rows) — a second consent problem; trigger:
  a real composer need that read-only context cannot express.
- **Unattended adaptive execution** (composed plans running without the plan-level
  park) — trigger: operational trust evidence from parked adaptive charters; its
  own consent decision.
- **Layer 1 — Live/Context Index** (REQ-013, B-009) — now with a named consumer
  (the composer's plan-time context) once v0.9 ships.
- **Layer 3 — Reasoning Retrieval** — **hard-gated** (any embedding/AI dependency =
  its own ADR against the offline + no-SaaS doctrine).
- **Computed `confidence`**; **a retention default on accrued rows** (trigger:
  observed growth); **multi-operator ACL + operator-read chaining** (SoD);
  **manifest-primary storage** — carried from v0.8.
- **The `internal/*` extraction; cron; DAG; the gateway exec worker; SSH pooling;
  full rate-limiting; TR-2** — unchanged prior deferrals.
