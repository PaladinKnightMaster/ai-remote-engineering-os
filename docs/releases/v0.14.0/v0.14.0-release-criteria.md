# v0.14.0 — Release Criteria

Status: **Accepted — 2026-08-19** (the v0.14 checkpoint consult; five decisions D1–D5 CEO-ratified on
the Commander recommendation after a pre-authoring audit that changed the scope twice). Acceptance of
this document fixes the release intent; thereafter changes require a new ADR (the v0.1.0–v0.13.0 rule).

The architecture ADR it depends on — **ADR-0071 (governed file transfer)** — is **Accepted** and was
authored alongside this document at T-137.

Owner: War Room Commander (synthesis); Backend Architect (the seam, the broker leg, bounds); Security
Reviewer (D7 scope gate, approval binding, negative proofs); UX Reviewer **for §7 only** (the approval
descriptor is operator-facing and a bad rendering makes the governance claim hollow).

Every criterion is *pass* (must be true), *block* (presence stops release), or *deferred* (explicitly
out of scope, with the trigger that promotes it back). A ticket is "done" when it closes one or more
criteria here and breaks none.

**No new criteria family is minted.** The tool family extends `SEC`/`AUD`/`CON`; bounds extend `PERF`;
verification extends `VER`. Minting a family per release is the habit structural rule #2 exists against.

---

## 1. Scope of v0.14.0 — and why it is a capability release

**v0.13.0 shipped zero features by design, and that was correct** — it answered the buyer question
with hardening. **Two consecutive capability-free releases would not be correct.** This release widens
the product's outward surface for the first time since v0.3.0.

### The diagnosis this release answers

The gateway registry holds six tools. Five are control-plane — they orchestrate this product. **One
reaches the outside world.** Six releases deepened the spine around a single capability; that
asymmetry, not any missing control, is the gap. The most conspicuous absence is file transfer:
`grep -rn "sftp\|scp"` over the repository returns nothing.

### D1 — Story disposition (**RATIFIED 2026-08-19**)

**In:** the `remote.file.*` family (read / write / list) on the agent-direct path, the plane-agnostic
seam that admits it, the broker file leg, the approval descriptor, the SEC-16 scope narrowing, and the
operator rendering of a file invocation.

**Out, by decision not omission:** file steps in Runs and Workstreams (ADR-0071 D6 — it changes the
OpenAPI fragment, and the freeze lands at v1.0.0); recursive/glob transfer; resume and chunking;
screenshare / remote PC control (deferred at the checkpoint to a deliberate two-release program);
containment (B-040, deferred with its consequence recorded).

### Hard constraints (the release's defining posture)

| # | Constraint |
|---|---|
| **C1** | **Zero OpenAPI fragment change.** Gateway tools are an MCP surface. If a ticket needs a fragment change, it is out of scope or needs a new ADR. |
| **C2** | **No new daemon, no new datastore, no new network path, no new key.** The broker stays the sole SSH egress (SEC-18). |
| **C3** | **No new capability edge.** File tools ride `agent-remote-session` (ADR-0071 D1). |
| **C4** | **No migration.** Token operations and grant verbs are already free-form text arrays. If a ticket needs a migration, the scope is wrong. |
| **C5** | **Nothing above the seam changes.** The concurrency cap, approval park, idempotency, fail-closed rule and audit brackets are untouched. |

**The boundary rule holds:** this release adds governed capability on an existing boundary. It does not
place the trust root on a new dependency (`pkg/sftp` is a pure-Go library inside the existing broker,
not a daemon, not a trust anchor).

## 2. The gate — **no new WD** (structural rule #2, re-tested)

A new WD-N is minted only when a release adds new **governed capability semantics** — a new edge, a new
trust boundary, a new consent model. This release adds tools on an existing edge, through an unchanged
governance pipeline, with an unchanged approval primitive.

**Gate = WD-1..11 regression on both stacks + smoke + the §7 capstone + a CEO §human pass.**

| ID | Criterion | Type |
|---|---|---|
| **VER-17** | WD-1..11 green on compose **and** the installed stack. The installed run rebuilds the offline bundle **and** the postgres companion from HEAD first (the standing T-033 + companion-staleness lesson). | pass |
| **VER-18** | `task smoke` green, extended with at least one file-tool leg. | pass |
| **VER-19** | CEO §human pass: mint a scoped token, read a file, write a file under approval, watch a denial. **This is the release's first real dogfooding contact** — findings are recorded, not suppressed. | pass |

⚠ **If any of §5's negative proofs cannot be made to fail correctly, this release does not ship.** A
guard that has never been observed failing is not a guard (VER-16, generalized).

## 5. Authority and the negative proofs (must-pass) — `SEC`

**These are the release's real gate.** Two of the three must be *observed failing correctly*.

| ID | Criterion | Type |
|---|---|---|
| **SEC-48** | **The SEC-16 narrowing (ADR-0071 D7).** An agent token with an **empty** operations list is **rejected** for `remote.file.read` and **accepted** for `remote.exec` — asserted in one test, so the distinction itself is under test. ⚠ **Negative proof: must be seen to fail.** | block |
| **SEC-49** | **Approval binds to the digest.** Content whose sha256 differs from the approved descriptor is **refused** at execution, not written. The v0.3.0 approved-command-swap closure is the precedent and must hold on this path. ⚠ **Negative proof: must be seen to fail.** | block |
| **SEC-50** | A grant or token naming `file.read` does **not** confer `file.write`, and neither confers `exec`. | pass |
| **SEC-51** | The broker's `/v1/file` leg carries the R5-ext subject pin — a service token from any workload other than `mcp-gateway` is rejected 403, mirroring `/v1/exec`. | pass |

## 6. Evidence and audit (must-pass) — `AUD`

| ID | Criterion | Type |
|---|---|---|
| **AUD-41** | Every file operation is bracketed `tool.invoked` / `tool.result` on the `agent-tool` edge, anchored `invocation:<id>` — identical in shape to exec. | pass |
| **AUD-42** | The broker records `Evidence sha256:<bytes>` for transferred content. **Raw file content never enters the audit chain, in either direction.** | pass |
| **AUD-43** | The audit chain verifies INTACT across a run containing file operations, and `aireos-verify` still reports `INTACT+ATTESTED` on an export covering them. | pass |
| **AUD-44** | A denied or failed file operation is audited with its terminal outcome; a refused over-cap transfer is `failed`, not silently dropped. | pass |

## 7. Operator surface (must-pass) — `FE`

| ID | Criterion | Type |
|---|---|---|
| **FE-43** | The approval prompt renders the ADR-0071 D3 descriptor — operation, path, size, digest, mode — legibly. **A descriptor the operator cannot parse makes the governance claim hollow**, which is why UX review is in scope for this section alone. | pass |
| **FE-44** | `/invocations` renders a file invocation without leaking raw content and without breaking the existing exec rendering. | pass |
| **FE-45** | Browser-rendered evidence (screenshot or a passing Playwright assertion against the rendered DOM) for both. jsdom does not satisfy this (CLAUDE.md §Definition of done). | pass |

## 8. Bounds and resource safety — `PERF`

| ID | Criterion | Type |
|---|---|---|
| **PERF-17** | Maximum transfer size is configurable, defaults to **1 MiB**, enforced in both directions. | pass |
| **PERF-18** | **The read path refuses an over-cap file rather than truncating it** — deliberately unlike exec's stdout truncation, because a truncated file is a corrupt file and a digest that matches nothing (ADR-0071 D5). | pass |
| **PERF-19** | Per-operation timeout mirrors exec's; over-cap, timeout, permission-denied and no-such-path all fail closed (SEC-19) and mark the invocation `failed`. | pass |
| **PERF-20** | The per-initiator concurrency cap applies to file operations unchanged — they are invocations. | pass |

## 14. Deferred (with promotion triggers)

Carried verbatim from ADR-0071 §Deferred: file steps in Runs · recursive/glob transfer · resume and
chunking · file operations in the cockpit UI beyond approval rendering · a `host.metrics` family on the
same seam. Plus, from the checkpoint: **screenshare / remote PC control** (two-release program, after a
dogfooding pass) and **containment B-040** (deferred with the cooperative-governance consequence
recorded in `epic_story_catalog_v4.md` §Part 4).

## 15. Designated drop candidate

**`remote.file.list` (T-142), in that order alone.** Cleanly severable: it shares `file.read`'s verb,
adds no governance semantics, and `remote.exec` can list a directory today. Dropping it costs
ergonomics, not the release's claim.

**Irreducible core (never drop):** the seam (T-138) · the broker leg (T-139) · `read` and `write`
(T-140, T-141) · both negative proofs (SEC-48, SEC-49) · the capstone.

Recorded here in advance, per VER-10, so a cut is a decision rather than an improvisation — the gap
v0.13.0 shipped with and had to fix mid-ladder.
