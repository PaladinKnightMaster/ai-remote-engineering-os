# v0.17.0 "Install & First-Run Experience" — release criteria

**Status: scope RATIFIED 2026-10-26 (CEO).** Authored in the Commander seat. Ladder tickets are JIT-authored
(§10); the two new ADRs (§7) are written and accepted **before** the tickets that build them.

---

## 1. Scope — and why this release exists

v0.16.0 made the product publishable and proved, with a real fresh-host run, that **the product works and
installing it is still hard**. The CEO's PUB-6 re-run passed, but only after a fix pass. The
guide-friendliness pass (T-167) then named the three places a stranger still stumbles, and two of them
**cannot be fixed by documentation**:

1. the installer makes you choose a database password and **type it into a URL by hand** — product;
2. you must **copy the key fingerprint** from the Releases page into the check — inherent to out-of-band
   verification, so it stays; this release makes it the *only* such step;
3. the quickstart makes you **switch between the server's terminal and the browser** — `generate`, then
   Create, then `bind` — before anything governed happens — product.

And behind them, the one known install failure: the PostgreSQL companion **fails on any server patched
after it was built** (R1, present since v0.1.0, stated in v0.16.0's known limitations).

**The question this release answers:** *can someone who rarely uses a terminal get from the downloaded
files to a completed, audited governed action, on any patched supported OS, typing at most three commands
on the server?* Today the guides ask for **22 command lines** on the server, counting `cd` [ran: count of
the fenced commands in the install guide's user path and the quickstart, 2026-10-26].

**The shape, ratified by the CEO (direction 2026-10-25):** **one command on the server, then everything
else in the browser.**

| Workstream | What | Decided by |
|---|---|---|
| **A. Self-contained PostgreSQL** | Source-built PostgreSQL 16 tree under `/opt/aireos/pgsql`, privately bundled libraries, its own `aireos-postgres.service`, **no host package manager** — fixes R1. OS scope: **Ubuntu 24.04, Ubuntu 26.04, Rocky/RHEL 9** | **ADR-0077 (Accepted 2026-10-26)** |
| **B. One-command setup** | `sudo ./setup.sh` installs PostgreSQL and the application together, **creates the database password itself and wires the URL**, and prints the one address to open | this document (installer behaviour; no new trust decision) |
| **C. Browser first-run setup** | The first operator account is created **in the browser**, gated by a **one-time setup code** the installer prints on the server | **ADR-0078 (Proposed 2026-10-26)** |
| **D. Browser-driven first target** | A target's SSH key is **generated inside the connector** (the sole decrypt authority, ADR-0053); the cockpit shows only the public half. The loopback demo needs **no server command** after setup | **ADR-0079 (Proposed 2026-10-26)** |
| **E. Installer residuals** | Warn when the site address is not on this server (v0.16.0 P8); after (re)starting services, **check they stayed up and Caddy answers** before printing DONE (T-165 residual) | v0.16.0 §8 |

**Explicitly NOT in scope:** B-041 harness integration (v1.0.0 Beta 1), containment (B-040), operator
visibility of command output (v0.16.0 P15b — an ADR question for Beta 1 scoping), and any change to the
governance chain itself (policy → approval → connector → broker). ⚠ Workstreams C and D change **what a
browser session can do on the host**; that is why each has its own ADR, and why §5 is the largest section.

## 2. The gate — NO NEW WD, and the stranger test is the gate

By the standing gate-sizing rule — *a new WD only for new governed capability* — this release mints none:
nothing new is governed. It changes how the product is installed and first configured.

**The gate is instead:**
1. **PUB-6 by a stranger who is not the CEO** (HUM-1) — the only instrument that has ever caught this
   product's install defects, and v0.16.0 showed it must be run by someone who did not write the docs;
2. the **later-host test** ADR-0077 D7 requires, with the v0.16.0 companion as its **negative control**;
3. the **SEC** negative proofs in §5 — every new trust boundary must be shown to refuse what it should;
4. **WD-1..15 regression** on both stacks plus `task smoke`.

## 7. ADR dependencies

- **ADR-0077 (Accepted 2026-10-26)** — self-contained PostgreSQL, OS scope extended to Ubuntu 26.04.
- **ADR-0078 (Proposed 2026-10-26, T-169) — first-run setup.** Drafted against this checklist; it must decide at least: how the code is generated,
  shown and stored; its lifetime and single use; lockout; what "setup complete" means and how it is made
  irreversible; what happens if the operator loses the code (re-issue from the server, never from the
  browser); and **why an unauthenticated window on a LAN is acceptable at all**, against the alternative
  of keeping first-operator creation in the terminal.
- **ADR-0079 (Proposed 2026-10-26, T-170) — connector-generated target credentials.** Drafted against this checklist; it must decide at least:
  key type; where generation happens (the connector, as sole decrypt authority — ADR-0053); how the
  public half reaches the operator; **how the loopback demo's `authorized_keys` entry gets installed
  with no server command** (likely a narrowly scoped, opt-in install-time step — the ADR must say what it
  is allowed to touch); and whether operator-imported keys remain supported.
- ⚠ **If any ladder ticket needs a further ADR, that is the signal it has left scope** (v0.16.0 §7 rule).

## 9. Recorded risks

1. ⚠⚠ **The project starts owning PostgreSQL security updates** for the bundled tree, and for every library
   it bundles (ADR-0077 Consequences). A PostgreSQL minor release with a security fix now means a new
   companion. **Accepted deliberately**, and stated in the release notes — an air-gapped host could never
   `apt upgrade` the old companion either.
2. ⚠ **Workstreams C and D open a browser path to actions that used to need root on the server.** That is
   the point of the release and its main risk; §5 is sized accordingly. ADR-0078/0079 must be accepted
   before C/D are built.
3. **Three OSes, built from source, each tested on a later host** is the largest build-and-test surface the
   project has taken on. Rocky has no recent baseline at all. ⓘ An `ubuntu:26.04` image exists for `amd64` [ran:
   `docker manifest inspect ubuntu:26.04`, 2026-10-26]; T-171 must still pin it by digest.
4. **Scope is four workstreams plus residuals**, two of them security-sensitive. If the ladder slips, the cut
   order is: E (residuals) first, then D's general-target half (keeping the demo), never A — **A is the
   P0 fix that blocks v1.0.0**.
5. **HUM-1 needs a human who is not the CEO.** Without one, this release cannot meet its own gate; recruit
   before the capstone, not at it.
