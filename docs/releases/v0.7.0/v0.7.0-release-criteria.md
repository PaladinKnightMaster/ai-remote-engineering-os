# v0.7.0 — Release Criteria

Status: **Accepted — 2026-07-05** (v0.7 criteria consult + a CEO-requested pre-accept
double-check whose six findings — the dead-grant self-retire, the charter-time
template-vs-bounds validation, the corrected N1 sequencing, the rolling-strict window
semantics + N3 construction, the installed-WD-7 scope split, and the broadened SEC-30 —
are baked in below; CEO sign-off). The single architecture ADR it depends on
(**ADR-0063 — Chartered Workstreams**) is already **Accepted** (`eb1abba`); acceptance of
*this* document fixes the release intent. Future changes to this document require a new
ADR (criteria drift is a load-bearing decision — the same rule as v0.1.0–v0.6.0).

Owner: War Room Commander (synthesis); Workstream Architect (charter/schedule/lifecycle);
Permission Model Reviewer (the `workstream:<id>` actor + the one-validator rule + the
consent-in-time coarsening); Audit/Evidence Reviewer (`workstream.*` lifecycle events +
provenance + evidence accrual); Offline-Install Engineer (OI-14 — an api migration only;
no new unit, route, key, or required env).

This document defines what shipping **v0.7.0 — "Chartered Workstreams" (the standing
objective that creates Runs)** means. Every criterion is *pass* (must be true), *block*
(presence stops release), or *deferred* (explicitly out of scope, with the trigger that
promotes it back). The criteria are the exit gate for every v0.7.0 ticket: a ticket is
"done" when it closes one or more criteria here and breaks none.

---

## 1. Scope of v0.7.0

v0.7.0 is the **third initiator** for the Run engine (ADR-0061) and the chartered module
it reserved the name for: where v0.5 let an **operator** launch a governed Run and v0.6
let an **agent** launch one under a delegation grant, v0.7 lets a **schedule** launch
governed Runs **with nobody present** — bounded by the charter's own auto-issued grant.
The Run engine, the grant machinery, `/v1/steps`, policy → connector → broker, and the
audit chain are **reused unchanged**; there is **zero gateway diff** this release.

**The privilege delta (ADR-0063).** A schedule tick has no launch-time party at all — no
human (v0.5's pillar) and no agent (v0.6's plan-composer). The authority must therefore be
*standing, bounded, revocable, consented-to in advance* — which is **exactly the ADR-0062
delegation grant**. Chartering auto-issues the Workstream's own grant in the same
transaction (grantee = `workstream:<id>`); **no third authority model exists**. Consent
generalizes in **time**: per-plan (v0.5) → per-grant (v0.6) → per-charter covering future
scheduled firings of a **reviewed, immutable template** (v0.7).

**Hard constraint (preserved).** Nothing new mints; nothing new is agent-reachable; `api`
and the gateway remain the sole signing authority; the gateway remains the sole
governed-step orchestrator; the broker remains the sole SSH egress. v0.7.0 adds **no new
egress path, no new credential custody, no new key, no new token-minting workload, and no
new agent-facing surface** — the Workstream is an api-internal initiator; the launch never
crosses the gateway (the sequencer picks up the Run rows it creates).

Concretely, on top of the v0.5/v0.6 engine, v0.7.0 delivers:

- **The charter primitive** — `workstreams` + `workstream_steps` in `services/api`
  (`internal/workstream`, the sibling seam): objective + an **immutable, sealed plan
  template** + a bounded scope + a fixed-interval schedule + bounds, with the charter's
  **auto-issued 1:1 delegation grant** created in the same transaction.
- **The in-process ticker** — a third api background goroutine that fires charters on
  their schedule via a **shared bounded-launch core** (one validator with the gateway
  forward), riding the existing sequencer with zero engine changes.
- **The windowed step budget** — an additive, nullable generalization of the grant budget
  so a standing charter cannot brick on v0.6's cumulative-forever semantics.
- **The lifecycle** — pause (soft) / resume / retire (revokes the grant → the existing
  cascade), plus **self-retire on a dead grant** (the double-check's F1), and the
  `/workstreams` operator surface whose run history + evidence links are the v0.7 slice
  of **scoped memory**.

**Out of scope** (→ §14): cron-expression schedules; agent-composed plans inside a
Workstream; charter sources/rules fields; the `internal/run`+`internal/grant` extraction;
parallel/branch/retry DAG; the gateway exec worker; fine-grained grant policy; SoD; the
full Memory/Context Index; SSH pooling; full rate-limiting; TR-2.

The wedge is **one chartered Workstream that fires on its schedule with nobody present,
drives a governed Run through the unchanged chain — unattended where ungated, parked where
flagged — accrues evidence to the charter, provably recurs, and stops when told to**
(WD-7). Everything else exists to make that true and verifiable.

## 2. WD-7 — the single load-bearing wedge (the demo)

**WD-7.** On a real (not mocked) stack, an operator charters a Workstream and **the
schedule autonomously creates and drives grant-bounded Runs**. WD-7 comprises a **happy
path** (1–5) plus three independent **live negatives** (N1 retire, N2 pause/resume, N3
budget-window recovery):

1. **Charter = one consent act.** The operator charters a Workstream (objective; an
   ordered template mixing an ungated R1 + a `requires_approval`-flagged R2; verbs
   {`exec`}; an interval; TTL + bounds + a windowed step budget). `workstream.chartered`
   **and** the auto-issued grant's `grant.issued` chain from the **same transaction**
   (actor = operator, `human-agent`, CSRF-gated). The template is **immutable** from this
   moment (no edit route exists — asserted).
2. **A tick fires with nobody present.** At `chartered_at + interval` (first fire — no
   immediate fire; the cron convention), the ticker claims the charter (single-winner,
   status-guarded), instantiates the template, and launches through the **shared bounded
   launch core** with launch key `workstream:<id>:tick:<t>`. `run.launched` chains with
   **actor = `workstream:<id>`, principal = the operator, grant_id**. The existing
   sequencer drives the Run.
3. **Unattended + parked.** The R1 step runs **unattended**; the R2 step **parks** on the
   existing `/invocations` console carrying its context (the workstream actor + the
   principal + the grant + the run) beside the verbatim command. A live operator approves
   → the Run completes.
4. **Evidence accrues to the charter.** The charter's detail view lists the Run with its
   evidence-packet linkage (grant id, principal, actor = the workstream, ordered steps,
   decisions, approvals, stdout-SHAs) — read-time assembly, chain hash-intact and
   replayable (`audit-service verify`).
5. **Recurrence is proven live.** A **second tick** fires after the next interval and
   completes — the schedule demonstrably recurs (compose e2e; see the installed-scope
   split below).

**Live negatives (separate charters, all live in the gate):**

- **N1 — retire is the kill switch.** A charter with an **in-flight** (parked) Run is
  retired: in one transaction the charter goes `retired` + its grant `revoked`
  (`workstream.retired` + `grant.revoked` chained), the existing cascade **cancels** the
  in-flight Run (`run.canceled`; the parked step deny-released per the running-orphan
  policy), and **no further tick ever fires — asserted by absence** across ≥1 elapsed
  interval. *(Corrected sequencing: a retired charter never claims — the ticker predicate
  is `status='active'` — so no post-retire plan-vs-grant denial occurs on the happy
  ordering. The claim-before-retire race, where a straggler launch hits the revoked grant
  and is denied + audited, is covered by design (SEC-29) and documented, not gated.)*
- **N2 — pause/resume.** A paused charter fires **nothing** across ≥1 elapsed interval
  (asserted by absence + no new Runs); an in-flight Run under pause **completes** (soft
  semantics); **resume re-arms `next_fire_at = now + interval`** (no catch-up fire) and
  the next tick fires.
- **N3 — budget exhaustion never wedges, and the window recovers.** A charter with
  **window = 2× interval and budget = one template**: tick 1 fires and completes; tick 2
  is **refused within the window** (`run.launch.denied` audited; HTTP-level 429 class;
  the charter stays `active`); tick 3 — the next window — **fires and completes**. Proves
  the windowed budget, the never-wedge property, and the rolling-strict semantics in one
  deterministic three-interval leg.

**Self-retire (F1) is gated with N1's family:** a charter whose grant is **dead**
(directly revoked via `/v1/grants/{id}/revoke`, or expired) is **retired by the ticker on
its next tick** (`workstream.retired` with a machine reason) instead of spinning eternal
denials — proven live with a direct grant revoke (whose v0.6 cascade already canceled the
charter's Runs by `grant_id`).

**Regression guards (elevated this release).** **WD-6 stays green** — the launch-core
split (§4/SEC-30) refactors `LaunchDelegatedRun` itself, so the agent-delegated path is
re-proven behavior-preserving **before** the ticker rides the shared core. **WD-5 stays
green** (operator Runs). Missed-ticks-collapse and the single-winner claim are
integration-tested off-gate (the PERF precedent).

**Installed scope (the F5 split).** The full WD-7 (incl. the second-tick recurrence leg)
runs on the compose e2e at the e2e interval floor (~5s). The **installed** stack keeps the
60s production floor, so the installed WD-7 (`task wd1`) runs **one fire + park→approve→
complete + retire** (~90s of schedule wall-clock) — recurrence is compose-proven. Stated
here so T-077 does not re-litigate it.

**This demo (happy path + N1 + N2 + N3 + self-retire) is the release gate** — built as an
extension of the `tests/e2e` live harness and re-run (at the installed scope) on the
installer-produced stack.

## 3. Capability-edge security (must-pass)

Every boundary stays gated by `packages/go/middleware` `RequireCapability`. v0.7.0 adds
**no new edge and no new plane**: chartering rides `human-agent` (cookie + CSRF); the tick
is api-internal (no token crosses a boundary at launch); the per-step path is the
unchanged ADR-0062 flow with actor = `workstream:<id>`.

- **SEC-30 (block) — one validator, two callers (both cores).** (a) **Launch:**
  plan-vs-grant (SEC-29) + the PERF bounds are enforced by a **single shared function**
  used by both the gateway forward (`LaunchDelegatedRun`) and the ticker — the in-process
  path enforces **identical** checks by construction, proven by the shared core + WD-6
  staying green. (b) **Issuance:** the grant-issuance bounds (`maxConcurrentRunsCeiling`,
  positive bounds, resource/verb caps) are enforced by a **shared helper** used by both
  `CreateGrant` and the charter route (which issues its grant in-process, bypassing the
  HTTP handler). A second diverging validator on either core is a release blocker.
- **SEC-26..29 (block, carried).** The agent-delegation invariants are preserved
  unchanged: the grant stays a server-side record (SEC-26); the launch surface stays
  keyless and `api` non-agent-reachable (SEC-27 — untouched: the Workstream adds no
  agent-facing anything); actor/principal binding + untouched subject-pins (SEC-28);
  plan-vs-grant as the enforced scope (SEC-29 — now via the shared core).
- **SEC-20/21/25/17/18 (block, carried).** Keyless gateway; no foreign-edge mint; no
  gateway decrypt path; broker pin + exec parity; step-pin discipline. **Zero gateway
  diff** is itself a criteria statement: any gateway edit in v0.7 must be explicitly
  called out at its ticket consult (none is planned).
- **Policy subject = the Workstream** (`workstream:<id>`): ADR-0054 same-operator
  self-approve stays defeated with nobody present; approval gating remains
  resource-label-driven, so the novel subject neither self-allows nor needs a policy
  entry (the v0.6 D3 verification carries).

## 4. Workstream architecture (must-pass)

- **WS-1 (block) — the charter primitive.** `workstreams` + `workstream_steps` tables +
  a self-contained `internal/workstream` store (the sibling seam: pgx pool + outbox
  writer only). The template's commands are **sealed at rest via the same nil-safe
  `CommandSealer` the Run store uses** (operator-authored command material; F3 parity).
  **The template, scope, and schedule are immutable post-charter** — no update route
  exists (edit = retire + re-charter; consent binds to the reviewed artifact). Status
  `active` / `paused` / `retired`; schedule = `interval_seconds` + durable
  `next_fire_at` (restart-safe).
- **WS-2 (block) — the charter auto-issues its grant, in-transaction.** Chartering
  creates the Workstream **and** its delegation grant (grantee = `workstream:<id>`,
  principal = the chartering operator, scope/TTL/bounds from the charter, 1:1) in one
  transaction, with `workstream.chartered` + `grant.issued` in the same tx.
  **Charter-time validation (422):** template ⊆ scope; `len(template) ≤
  max_steps_per_run` **and** `≤ step_budget` (no wedged-by-construction charter — F2);
  `interval ≥ the floor`; the shared issuance bounds (SEC-30b).
- **WS-3 (block) — ticker semantics.** A third in-process background goroutine (the
  reaper/sequencer pattern) — no cron daemon, no new unit. **First fire = `chartered_at +
  interval`** (no immediate fire). Fire = a **single-winner, status-guarded claim** that
  advances `next_fire_at` from *now* (**missed ticks collapse to one** — no backfill).
  Launch key `workstream:<id>:tick:<t>` rides the existing `(grant_id, launch_key)`
  dedup (a re-fired tick re-attaches — no double-launch). A **transient** bounds refusal
  (budget window / concurrency / the per-operator ceiling) audits `run.launch.denied`
  and the charter simply fires again next interval — **a refused tick never wedges or
  retires a charter**. A **dead-grant** refusal (revoked or expired) **self-retires** the
  charter (F1): `workstream.retired` with a machine reason; uniform for direct-revoke and
  expiry.
- **WS-4 (block) — the windowed step budget.** `delegation_grants` gains a **nullable
  `budget_window_seconds`**. Semantics: **rolling window, strict inequality** — the
  budget counts planned steps of the grant's Runs with `created_at > now() − window`.
  **NULL = the v0.6 cumulative semantics unchanged** (behavior-preserving; no existing
  grant changes meaning). Charter grants set it (default = the interval; the boundary
  note: with window = interval, the previous tick's Run sits at the strict boundary and
  the ticker's scan lag keeps steady-state ticks passing — stated, not discovered).
- **WS-5 (block) — lifecycle verbs.** **Pause** (reversible): ticks stop (the claim
  predicate), in-flight Runs **complete**, the grant stays active; **resume** re-arms
  `next_fire_at = now + interval`. **Retire** (terminal): one transaction flips the
  charter `retired` + the grant `revoked`, then the existing cascade cancels the grant's
  active Runs. The v0.6 documented residual carries honestly: the post-tx cascade is
  best-effort/non-atomic (a crash between the tx and the cascade leaves bounded,
  self-completing Runs; no security impact).
- **Extraction stays deferred (pass).** Workstreams ride the api-local sibling seams; no
  `services/workstream-engine` is extracted (the trigger — an out-of-process consumer —
  is unfired and was **strengthened** by the scoping audit).

## 5. Governance & consent (must-pass)

- **GOV-8 (block) — the charter is the one explicit consent act, and the coarsening is
  in time.** Issuing a charter consents to **future scheduled firings** of the reviewed
  template within the reviewed scope/bounds — stated plainly here and in the charter UI.
  The consent object is **immutable** (WS-1); v0.6's resource+verb granularity is
  unchanged — what v0.7 adds is recurrence, contained by §10's quadruple bound.
- **GOV-5/6 (block, carried).** Flagged steps **park** for a live human on the existing
  `/invocations` surface, carrying the delegated context (actor = the workstream ·
  principal · grant · run) beside the verbatim command (operator-only, ADR-0059). Ungated
  steps run unattended.
- **GOV-7 (pass, carried).** An operator can only charter within authority it holds
  (single-bootstrap-operator posture; narrows with multi-operator; SoD stays deferred).

## 6. Durability & lifecycle (must-pass)

- **DUR-8 (block) — schedule durability.** `next_fire_at` is durable (an api restart
  mid-interval fires on time, not from scratch); tick idempotency via the launch-key
  dedup; missed ticks collapse; the single-winner claim tolerates a crashed ticker (the
  next scan re-claims — deployment is single-node, correctness doesn't rely on it).
- **DUR-1..7 (block/pass, carried).** The Run engine's durability is reused unchanged for
  workstream Runs — same `runs`/`run_steps`, same sequencer, same reclaimable claim,
  resume-with-skip, fail-closed orphan, cancel, revocation cascade (DUR-7 now also
  triggered by retire), and non-atomicity as an explicit non-guarantee.

## 7. Audit & Evidence (must-pass)

- **AUD-18 (block) — workstream lifecycle events.** `api` chains `workstream.chartered`
  / `workstream.paused` / `workstream.resumed` / `workstream.retired` via its
  transactional outbox — content-free (the objective/template are referenced, never any
  command); `workstream.chartered` + `grant.issued` share a transaction (WS-2);
  `workstream.retired` carries a machine reason distinguishing operator-retire from
  self-retire (actor semantics nailed at the T-074 consult). Provenance: a workstream Run
  is distinguishable in the chain by its actor prefix (`workstream:<id>`) + principal +
  grant_id + the `run:<id>` anchor (AUD-17 carried; the single hash chain stays intact +
  replayable).
- **EVD-4 (pass) — evidence accrues to the charter.** The charter detail assembles its
  run history with evidence-packet linkage at read time from existing durable state (the
  EVD-1 contract — no new blob, no index): each Run's grant id, principal, actor, ordered
  steps, decisions, approvals, stdout-SHAs. This is the v0.7 slice of scoped memory; the
  Memory/Context Index module stays deferred with the Workstream as its future owning
  entity.

## 9. Offline install & operability (must-pass)

- **OI-14 (block).** Everything ships **inside `services/api`**: one migration (the
  `workstreams`/`workstream_steps` tables + the `budget_window_seconds` column) run by
  the existing `install.sh` migrate loop. **No new systemd unit, no new Caddy route, no
  new key material, no new required env** — the ticker is in-process and the interval
  floor is an optional override (`AIREOS_WORKSTREAM_MIN_INTERVAL_SECONDS`, default 60,
  not written by `install.sh` — the installed stack asserts the default posture). A
  fresh installer-driven boot brings the stack `active` and the **installed-scope WD-7
  passes** (`task wd1`; the F5 split — one fire + park/approve + retire); `task
  offline-bundle`'s size gate holds; **bundle rebuilt from HEAD before the run** (the
  t033 lesson). No SaaS runtime dependency.

## 10. Performance & resource safety (must-pass)

- **PERF-8 (block) — the runaway-schedule containment (the one new vector).** Quadruple
  bound: **(1)** the interval floor — 60s production default, env-overridable (the e2e
  compose sets ~5s to prove live recurrence); charter-time 422 below the floor; **(2)**
  the per-grant `max_concurrent_runs` ≤ the gateway in-flight cap (4) — the v0.6 PERF-7
  reconciliation carried; **(3)** the windowed step budget (WS-4); **(4)** the
  per-operator active-Run ceiling (10) — workstream Runs set `runs.operator = principal`
  and count against it (cap layering carried; a ceiling-refused tick audits + re-fires,
  never wedges). Flagged resources still park regardless.
- The v0.3–v0.6 floors (PERF-1..7) are unchanged. SSH pooling + full per-edge
  rate-limiting remain **deferred** (§14) — the interval floor + the grant bounds are the
  scheduled-load governors at this scale.

## 13. ADR dependencies

- **ADR-0063 — Chartered Workstreams (Accepted `eb1abba`).** The sole new ADR. Settles:
  the immutable-template charter; the auto-issued 1:1 grant as the sole authority (no
  third model); the windowed budget (nullable, NULL = v0.6 semantics); the shared
  bounded-launch core; the no-cron in-process ticker (single-winner claim, no backfill,
  first fire = charter + interval); actor = `workstream:<id>` on the unchanged
  actor/principal split with the `agent-tool` edge's ratified non-human-actor reading;
  pause-soft/retire-hard with the revocation cascade. The double-check's self-retire (F1)
  and charter-time template-vs-bounds validation (F2) are criteria-level clarifications
  within the ADR's stated 1:1-lifecycle and never-wedge intent (the v0.6 precedent for
  folding audit findings into criteria without ADR drift). Any divergence surfaced at a
  ticket consult files a new ADR.

## 14. Deferred (with promotion triggers)

- **Cron-expression schedules** — trigger: operator demand for calendar semantics
  (`interval_seconds` is the v0.7 shape; a cron parser is a new dependency).
- **Agent-composed plans inside a Workstream** (an agent authors each tick's plan against
  the objective) — trigger: a real objective a fixed template cannot express (the
  `run.launch` agent path already exists).
- **Charter sources/rules fields** — arrive with the **Memory/Context Index** (P2), which
  stays deferred with the Workstream as its future owning entity.
- **The `internal/run`+`internal/grant`(+`internal/workstream`) extraction** — trigger:
  a real out-of-process consumer (unfired; strengthened by the scoping audit).
- **Plan-level grant-with-preview** — absorbed for the scheduled case by the reviewed
  immutable template; anything beyond waits for ergonomic pressure.
- **Parallel/branch/retry DAG; the gateway exec worker; fine-grained (per-command) grant
  policy; SoD; SSH pooling + full per-edge rate-limiting; persisted-command GC; the
  per-workload key registry/JWKS** — unchanged prior deferrals.
