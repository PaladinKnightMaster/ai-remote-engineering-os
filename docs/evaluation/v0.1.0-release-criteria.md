# v0.1.0 — Release Criteria

Status: **Accepted — 2026-05-25** after war-room consult (12 findings folded
in across §3, §5, §6, §7, §8, §10, §11).

Owner: War Room Commander (synthesis); Permission Model Reviewer (security
gates); Frontend Lead (cockpit); Offline-Install Engineer (installer); Tech
Lead (codegen + audit chain).

Future changes to this document require a new ADR (criteria drift is a
load-bearing decision).

This document defines what shipping **v0.1.0 — P0 vertical slice** means.
Every criterion below is *pass* (must be true), *block* (presence stops
release), or *deferred-to-v0.2.0* (explicitly out of scope, with the
trigger that would promote it back).

The criteria are the exit gate for every future P0 ticket: a ticket is
"done" when it closes one or more criteria here and breaks none.

---

## 1. Scope of v0.1.0

The smallest demonstrable wedge from `docs/executive/north-star-roadmap.md`'s
P0 row:

> *Remote Cockpit, auth, DMZ/VPN, GUI/terminal sessions, basic board,
> audit, offline installer.*

Concretely for v0.1.0:

- **One operator** authenticates against a self-hosted instance,
- **lists resources** they're authorized to see,
- **starts a remote session** to a single resource (one terminal-type
  resource is sufficient; GUI Guacamole is hold-in-reserve — see §10),
- **operates it via the cockpit** (xterm.js terminal over WebSocket),
- **the session is audit-chained** end-to-end (capability mint, session
  start, every operator action, session end),
- **the entire stack runs from an offline-install bundle** on a host with
  no network egress to public registries,
- **and a reviewer can replay the audit trail** to verify what happened.

Anything beyond this set is **v0.2.0 or later**. See §10 for the explicit
deferral list.

## 2. Wedge demo (the single load-bearing criterion)

**WD-1.** A fresh installer-driven boot of the offline bundle produces a
running stack that passes the following scripted demo, end-to-end, against
a real (not mocked) target resource:

1. Operator visits `https://<host>/`, lands on `/login`.
2. Submits credentials → 200 + `aireos_session` and `aireos_csrf` cookies set.
3. Lands on `/`, sees the resource picker populated from
   `GET /v1/resources`.
4. Picks an SSH-typed resource → navigates to the session view.
5. The session view opens a WebSocket through `services/session-broker`
   to a real SSH backend; xterm.js renders the PTY.
6. Operator types a command (e.g. `whoami`); output renders.
7. Operator closes the session → session lifecycle terminates cleanly.
8. Operator visits the audit timeline → sees ordered, hash-chained events
   for: login, capability mint, session-start, every operator command,
   session-end, logout.
9. A reviewer can verify the chained-hash integrity of the events via a
   provided CLI (no external script).

**This single demo is the release gate.** Every other criterion below
exists to make this demo trustworthy, repeatable, and safe.

## 3. Capability-edge security (must-pass)

Closes: ADR-0043, ADR-0046, ADR-0047 — capability-edge UI + server-side
enforcement.

- **SEC-1.** Every operator-facing route on `services/api` and
  `services/session-broker` is gated by `mw.RequireCapability` over the
  declared edge from `docs/security/agent-permission-model.md`. Bypass
  attempts (no bearer, expired token, wrong audience, wrong edge) return
  401 / 403 deterministically.
- **SEC-2.** The operator session token (PASETO v4) is never exposed to
  JS by construction. Login sets `aireos_session` as
  `HttpOnly; Secure; SameSite=Strict`. The login response body MUST NOT
  contain the token. (T-007b satisfies; CI lint must enforce — see SEC-7.)
- **SEC-3.** Double-submit CSRF protection (`X-CSRF-Token` header equals
  `aireos_csrf` cookie) is enforced on every gated non-GET/HEAD request
  that arrives over the cookie path. Constant-time compare. (T-007b
  satisfies.)
- **SEC-4.** Sliding refresh rotates both cookies inline with the
  response when the operator's verified token is in the second half of
  its TTL. No explicit refresh endpoint exists.
- **SEC-5.** The single 401 chokepoint in `packages/shared-types/src/client.ts`
  clears the in-memory `<CapabilityProvider>` state via full-page reload
  to `/login`. No silent retry, no token re-use.
- **SEC-6.** Service-to-service traffic uses `Authorization: Bearer
  <service-PASETO>` with `edge: service-service`. The outbox relay's
  call to `audit-service` is gated identically to human traffic.
  (T-008 + T-004b satisfy.)
- **SEC-7. (BLOCKS RELEASE)** A passing JS-side lint suite enforces:
  - **No direct `fetch()` outside `packages/shared-types/src/client.ts`**
    — bypassing `createApiClient` silently disables CSRF + 401 chokepoint.
  - **No `dangerouslySetInnerHTML`** anywhere in `apps/web` /
    `packages/ui` — the cockpit renders operator-controllable content.
  - **No `localStorage.setItem("*token*")`** / equivalent regex —
    prevents accidental token persistence.
  - (T-012 lands these; without T-012 v0.1.0 cannot release.)
- **SEC-8. (BLOCKS RELEASE)** A passing Go-side lint suite enforces:
  - No import of `github.com/aidantwoods/go-paseto` outside
    `packages/go/auth/`.
  - No use of `dangerous` HTTP helpers (`http.DefaultServeMux`, etc.).
  - No `panic` in request-path code without recovery middleware.
  - (T-011 lands these; without T-011 v0.1.0 cannot release.)
- **SEC-9.** Every capability-token issuance and refresh emits a
  structured audit event via the ADR-0045 outbox path. The events MUST
  appear in the chained-hash log in canonical order (the AUD-6 / SEC-9
  cross-link: SEC asserts the trigger, AUD asserts the chain integrity
  of the emitted record). Specifically:
  - `auth.login.success` on every Login 200.
  - `auth.refresh` on every sliding-refresh cookie rotation.
  - `auth.logout` on every Logout 204.
  - `auth.service-token.mint` on every service-token issuance.
- **SEC-10.** **Token replay during TTL is accepted at P0.** Per
  ADR-0046, revocation = key rotation + short TTL (operator 8h, agent
  5min). A captured operator session cookie is valid for its remaining
  TTL. Mitigation = the `task auth rotate-key` operator action +
  HttpOnly + SameSite=Strict + audit-chain visibility of any
  post-compromise activity. Promotes to per-token revocation list the
  day operator count > 3 or JWKS rotation lands (per ADR-0046 review
  triggers).

**Known limit — Login CSRF.** `POST /v1/auth/login` is public and not
behind a pre-auth CSRF token. Documented in T-007b ticket. SameSite=Strict
blocks cross-site initiators; same-site initiators remain an unmitigated
attack class. **Status at v0.1.0: accepted.** Promotes to blocker when:
(a) the first enterprise customer requires AD/OIDC federation (a new ADR
adopts Zitadel), or (b) a same-site initiator vector is found in the
deployed stack. See `docs/tickets/T-007b-login-cookie-reconciliation.md`
§Known limit.

## 4. Audit-chain integrity (must-pass)

Closes: ADR-0045 — chained-hash audit authority.

- **AUD-1.** Every operator action that crosses a capability edge emits
  one or more events to `services/audit-service` via the producer
  outbox + sync HTTP append-only ingest path. No edge crossing is
  unaudited.
- **AUD-2.** The chained-hash integrity test (T-004b integration suite)
  passes under concurrent producers. `prevHash`/`chainHash` are
  server-assigned; client-supplied chain fields are rejected with 400.
- **AUD-3.** Idempotency: a replayed `idempotencyKey` returns the
  existing event unchanged. Tested in T-004b.
- **AUD-4.** Events surface in the cockpit audit timeline in ascending
  chain order with a forward-only cursor. Pagination respects the
  contract's `LimitParam` / `CursorParam`.
- **AUD-5.** A `task audit verify` (or equivalent) operator command
  re-walks the chain from genesis and reports a single `OK` or the
  first integrity-failing event. Required for the reviewer step of the
  wedge demo (WD-1.9).
- **AUD-6.** Token issuance + refresh emit structured audit events
  (per ADR-0046 §Verification §6). Sliding refresh in particular MUST
  emit a `auth.refresh` event.

## 5. Frontend cockpit (must-pass)

Closes: ADR-0047 — capability-edge UI + Vite SPA + offline-shippable
static assets.

- **FE-1.** `apps/web` builds to a directory of hashed static files
  with no Node runtime in the production artifact. (T-007c satisfies;
  re-verified on every release build.)
- **FE-2.** Bundle SLO: first-load **JS ≤ 600 KB gzipped**, first-load
  **CSS ≤ 50 KB gzipped**. The numeric ceiling sits above the known
  largest deps (`guacamole-common-js` ≈ 80 KB min, `xterm.js` ≈ 150 KB
  min, plus React + Router) with headroom for the resource picker +
  session view + audit timeline. **Enforcement mechanism**: any new
  dependency that pushes the gzipped JS past the SLO adds a
  supply-chain-review item to the introducing ticket (Permission
  Model Reviewer lens, war-room consult). The hard upper ceiling
  remains **1 MB gz** per ADR-0047's review trigger. T-007c shipped
  62 KB gz JS / 2.5 KB gz CSS — comfortable headroom today; re-eval
  per OQ-5 after the session view ships.
- **FE-3.** Capability-edge UI: `<CapabilityGate edge="...">` wraps
  every interactive control whose server-side handler has a non-empty
  allowed-edges set. **Review-enforced at v0.1.0 with no current
  automation plan** — a custom ESLint rule for "every interactive
  control has a CapabilityGate ancestor" requires JSX-tree analysis
  that's genuinely hard and brittle. Honesty over aspiration: this
  stays a code-review gate, with the offsetting protection that
  `RequireCapability` (ADR-0046) is the actual security boundary —
  a missed gate produces a wrong UX (button visible but 403s on
  click), not a security breach.
- **FE-4.** 401 chokepoint behavior verified end-to-end: an in-flight
  operator request that 401s redirects to `/login` exactly once, with
  no silent retry, no infinite-reload loop.
- **FE-5.** The three currently-deferred `packages/ui` components
  (`<ApprovalPrompt>`, `<RemoteSessionView>`, `<TerminalView>`) MUST
  land before v0.1.0 (each with its feature ticket). The session-view
  WebSocket integration is the load-bearing item.
- **FE-6.** Logout: `POST /v1/auth/logout` is surfaced via a logout
  button in the cockpit chrome. Clearing both cookies is verified.
- **FE-7.** Accessibility baseline (design-system-governance §):
  every form has labeled inputs, every error region has `role="alert"`,
  every interactive control reachable by keyboard. **Tool: `axe-core`**
  via `@axe-core/react` for dev-mode warnings and (when Playwright
  lands per §10) `@axe-core/playwright` for the CI a11y gate. Required
  passing routes at v0.1.0: `/login`, `/` (dashboard), the resource
  picker, the session view.

## 6. Offline install (must-pass — release vehicle)

Closes: ADR-0001, ADR-0041, ADR-0042 — self-hosted, single-static-binary,
offline-first.

- **OI-1.** `task offline-bundle` produces a tarball containing:
  - Per-service single static Go binaries (api, audit-service,
    session-broker, plus any v0.1.0 additions).
  - `apps/web/dist/` static assets.
  - Reverse-proxy binary + config (Caddy OR Traefik — see OQ-3).
  - Postgres init scripts + migrations under embed.FS in each service.
    (**Postgres binary itself: see OQ-6** — bundle either ships
    Postgres or requires it on the host.)
  - All Go module cache + pnpm content store needed for a no-network
    rebuild.
  - `install.sh` + first-boot operator provisioning helpers.
  - TLS cert material — self-signed at v0.1.0 unless OQ-7 settles
    otherwise.
  - `SHA256_MANIFEST.txt` covering every artifact.
- **OI-2.** `install.sh` on a clean host with no public-internet egress:
  - Generates a cluster PASETO key (`task auth -- genkey`).
  - Provisions exactly one bootstrap operator (argon2id-hashed) from
    interactive prompt or env vars.
  - Brings up postgres, applies migrations, starts every service.
  - Outputs the operator login URL + credentials reminder.
  - Idempotent: running twice produces the same end-state, no
    duplicate operator rows.
- **OI-3.** The wedge demo (WD-1) passes against this installer-produced
  stack with **no manual steps after `install.sh` exits**.
- **OI-4.** Bundle size budget: ≤ **500 MB uncompressed**, ≤ **150 MB
  gzipped**. Hard upper bound on shipping artifact.
- **OI-5.** `SHA256_MANIFEST.txt` verifies via a plain
  `sha256sum -c SHA256_MANIFEST.txt` on the unpacked bundle.

## 7. Supply chain (must-pass)

Closes: ADR-0001, ADR-0041, ADR-0042 — tight supply chain.

- **SC-1.** All Go runtime deps are pinned to exact versions in each
  service's `go.mod`. No `replace` directives pointing outside the
  workspace.
- **SC-2.** All JS runtime deps use `~` ranges (patch-only); devDeps
  may use `^`. `pnpm-lock.yaml` resolves every dep transitively.
  `frozen-lockfile=true` in `.npmrc` enforces.
- **SC-3.** `pnpm.overrides` in root `package.json` pins versions where
  multiple ranges resolve (currently: `vite: ~6.0.7`).
- **SC-4.** No npm package has an executed install-time script. The
  esbuild "Ignored build scripts" warning is the documented expected
  behavior; promote to explicit `pnpm.onlyBuiltDependencies: []` if a
  contributor needs to silence it.
- **SC-5.** `task validate` (Python OpenAPI + JSON-Schema fixtures)
  passes.
- **SC-6.** License posture: **permissive licenses + weak-copyleft
  acceptable; strong-copyleft (GPL family, AGPL) blocks.** Acceptable
  list at v0.1.0: MIT, Apache-2.0, BSD-2/3-Clause, ISC, MPL-2.0,
  LGPL-2.1/3.0 (linking exception only), Unlicense, 0BSD,
  CC0-1.0, Python-2.0. A `task licenses` (or equivalent) reports the
  full transitive set and exits non-zero on any unlisted license.
  Manual review at v0.1.0; the detailed policy + automation lands in
  `docs/security/license-policy.md` as a release-prep ticket.

## 9. Verification automation (must-pass — CI gate)

Closes: T-010 + extensions.

- **VER-1.** `.github/workflows/ci.yml` (or its post-remote successor)
  runs every gate that this document calls "must-pass" with a passing
  status. A failing CI run blocks release by definition.
- **VER-2.** The following commands run clean on every push to `dev`
  and on every fast-forward of `main`:
  - `go build` + `go vet` + `go test` across `packages/go/...` and
    `services/...`.
  - `go test -tags integration` against the docker-compose Postgres
    for `audit-service` and `api` store packages.
  - `task codegen` regenerates Go + TS; drift check via
    `git diff --exit-code` passes.
  - `task validate` (Python contract validator) passes.
  - `pnpm install --frozen-lockfile`.
  - `pnpm -r run typecheck`.
  - `pnpm -r --if-present run test` (all workspace JS tests).
  - `pnpm -r --if-present run lint` (lands with T-011/T-012).
  - `pnpm --filter @aireos/web run build`.
- **VER-3.** A `task release-check` aggregator runs all of the above
  in sequence and exits 0 only if every gate passed. Required for
  invoking the release build.
- **VER-4.** An end-to-end live test (curl-driven against the
  docker-compose stack with services/api booted + bootstrap operator
  provisioned) exercises the wedge demo (WD-1) headlessly. Pass/fail
  reported in CI.

## 11. Open questions (must be answered before release)

- **OQ-1.** Which xterm.js → backend bridge does `<TerminalView>` use?
  Direct WebSocket from session-broker to an in-process PTY, or
  session-broker → guacd? Decision needed before the
  `<RemoteSessionView>`/`<TerminalView>` feature ticket consult.
- **OQ-2.** What service owns "session lifecycle"? `services/api` (add
  `/v1/sessions` CRUD) or a new `services/session-manager`? Affects
  ADR-0043 §Verification scope. Decision needed before the session-
  lifecycle ticket.
- **OQ-3.** Does v0.1.0 ship with **Caddy** or **Traefik** as the
  reverse proxy? Deep-dive 09 lists both; pick one for the offline
  installer. Decision needed before OI-1.
- **OQ-4.** How does `install.sh` provision the bootstrap operator —
  interactive prompt only, env-var only, or both? Affects OI-2.
- **OQ-5.** Bundle SLO at FE-2 (600 KB gz JS / 50 KB gz CSS) is set
  with headroom; re-evaluate against measured size after the resource
  picker + session view ship. The hard ceiling stays 1 MB gz JS per
  ADR-0047.
- **OQ-6. (NEW)** Does the offline bundle SHIP postgres binary, or
  REQUIRE postgres on the host? Postgres image is ~150 MB — bundling
  it crosses OI-4 (150 MB gzipped tarball cap). The trade-off:
  ship-it = single-tar-install, simpler operator path; require-it =
  smaller bundle, one more host prerequisite. Decision needed before
  the `install.sh` ticket.
- **OQ-7. (NEW)** TLS certificate origin in the installer: (a) the
  installer generates a self-signed cert (works for localhost / LAN
  with operator-imported trust), (b) install.sh accepts a CA-issued
  cert at first-boot prompt, (c) ACME / Let's-Encrypt (requires
  internet, contradicts offline-first). Default lean: (a) for v0.1.0
  with (b) as documented escape hatch; (c) explicitly rejected.
  Decision needed before the `install.sh` ticket consult.
- **OQ-8. (NEW)** Browser support matrix at v0.1.0. Default lean:
  current Chrome, Edge, Firefox (latest two releases each); Safari
  best-effort but not gated. Confirm before FE-7 a11y gate runs.

Each open question is an explicit war-room consult before the ticket
that depends on it can be authored.

## 11a. Release-prep ticket triggers (must land before tagging v0.1.0)

These are utility / verification tickets that don't exist yet and gate
the release. They are tracked here (not in §10 — they're not deferrals,
they're prerequisites):

- **`task release-check` aggregator** (closes VER-3). Runs every
  must-pass gate from §3–§9 in sequence; exits 0 only if all pass.
- **`task doc-check` aggregator** (closes DOC-1's automation gap).
  Walks every relative-path reference in `CANONICAL_SOURCE_OF_TRUTH.md`
  + every ADR; asserts each resolves.
- **`task licenses` aggregator** (closes SC-6's automation gap).
  Reports the full transitive license set; exits non-zero on any
  unlisted license per SC-6.
- **`docs/security/license-policy.md`** — formalizes SC-6's
  acceptable-license list with the kit's rationale.
- **The `install.sh` ticket** — closes OI-1 through OI-5. Settles
  OQ-3, OQ-4, OQ-6, OQ-7 in its consult.
- **`docs/releases/v0.1.0/` artifacts** — release_notes,
  release_manifest, criteria archive copy (per DOC-6).

## 12. Verification command (the meta-gate)

The release is **green** when this passes:

```
task release-check     # aggregator from VER-3
```

…AND a human runs the wedge demo (WD-1) against the installer-produced
stack and confirms each of WD-1.1 through WD-1.9.

The human step is non-negotiable at v0.1.0. Automation lands with the
first Playwright e2e suite (deferred — see §10).
