# Business and Market Strategy

## Beachhead customers

- Secure software teams.
- Companies with no-SaaS or restricted-network policies.
- Manufacturing plants and internal support teams.
- Labs and R&D groups.
- Healthcare/finance/defense-adjacent teams.
- IT teams needing self-hosted remote support and demos.
- Developer teams wanting AI agents but requiring governance.

## Positioning

Do not position as another coding agent or another remote desktop tool.

Position as:

> Self-hosted agentic work execution for restricted engineering environments.

## Defensibility

Strong:

- self-hosted/offline runtime
- DMZ/VPN deployment templates
- mobile-first remote control
- audit and approval
- board-owned agent runs
- evidence packets
- integration of remote execution + agent execution + work management

Weak:

- generic remote desktop
- generic coding agent
- generic Jira clone
- generic wiki
- generic Git forge

## Business model options

- Open-core self-hosted.
- Enterprise support.
- Per-seat/per-device enterprise license.
- Air-gapped deployment package.
- Professional services for network deployment.
- Optional hosted demo/dev cloud later, but not runtime requirement.

## Launch narrative

Start with:

> Secure mobile/browser access to internal PCs and workspaces.

Then add:

> Agentic work board with approval and evidence.

Then mature into:

> Self-hosted AI-native engineering OS.
