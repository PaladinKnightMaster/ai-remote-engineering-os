# ADR-0041: Go as primary backend language; TypeScript for web frontend; Python as sanctioned AI sidecar

## Status
Accepted — 2026-05-16.

## Context

The v3.0.1 baseline mandates self-hosted deployment into restricted networks (DMZ/VPN/LAN), with offline-installable images and audit-grade tamper-evidence. ADR-0001 already established "self-hosted/offline-first is non-negotiable." The product positions on:

1. **Single-binary / minimal-runtime deploy** so air-gapped installs work on freshly-imaged hosts.
2. **Tight supply-chain surface** so security and audit reviews remain tractable.
3. **Capability-edge permission model** (`docs/security/agent-permission-model.md`) with typed edges for every cross-actor interaction.
4. **Append-only audit + chained-hash evidence packets** in the critical path of every action.
5. **Concurrency at the session broker and (P1) MCP gateway** for many simultaneous remote sessions and tool calls.
6. **P0 MVP velocity** — the wedge must ship.

P0 services to be written: `api`, `session-broker`, `audit-service`, `policy-service`, `connector-service`. The web app (`apps/web`) is browser-targeted, not part of this decision.

## Decision

- **Go** is the primary language for all P0 backend services and any P1+ services unless an explicit follow-up ADR exempts a specific module.
- **TypeScript** is used only for the web frontend (`apps/web`, `apps/admin` if scoped). Shared types with the backend flow through OpenAPI + JSON-schema codegen, not through a shared runtime.
- **Python** is sanctioned as a *sanctioned sidecar* for AI/ML tooling in P1+ (MCP gateway calls into Python services; workstream tooling). Sidecar services are invoked over typed RPC from a Go service that owns the audit/permission edges.
- **Rust** is held in reserve for a future hardened crypto/sandbox module if and only if a specific threat-model gap surfaces. Adopting Rust for a module requires a follow-up ADR.

The Go version target is the current Go stable release line at time of first service implementation. Toolchain version is pinned per service via `go.mod`.

## Alternatives considered

### TypeScript / Node primary
Rejected.
- Pros: fastest dev velocity, large ecosystem, shared Zod types with frontend, easiest AI vendor SDK story.
- Cons: bundling Node into a single binary requires `pkg`/`nexe` (fragile in restricted networks, large image baseline). Massive transitive npm dependency trees inflate the audit surface and increase supply-chain risk. Event-loop single-threaded I/O caps the session broker at the low tens of thousands of concurrent connections per process.
- Decisive: deployment posture and supply-chain surface conflict with the product wedge.

### Rust primary
Rejected for P0.
- Pros: strongest memory safety, best performance, compile-time enforcement of capability-edge invariants via `Send`/`Sync`/lifetimes, single static binary.
- Cons: slowest dev velocity for P0 MVP; smallest hiring pool; async ecosystem still fragmented; overkill for CRUD-shaped services (resource registry).
- Decisive: P0 velocity. Acceptable for a future hardened module (see "Held in reserve" below).

### Python primary
Rejected.
- Pros: best AI/ML ecosystem, fast prototyping, good readability.
- Cons: single-binary deploy is brittle (PyInstaller / Nuitka fail in restricted-network mirrors); GIL constrains concurrency for the session broker hot path; larger Docker images; weaker runtime schema enforcement; pip supply-chain incidents are documented.
- Decisive: deployment + concurrency mismatch.

### Polyglot (Go + TS + Python equally)
Partially adopted (see Decision). Rejected as a *primary* framing because letting every service pick its own language balloons operational complexity, fragments tooling, and makes capability-edge enforcement harder. Adopted in the constrained form: Go primary for backend, TS for frontend only, Python sanctioned as sidecar for AI/ML only.

## Consequences

### Positive
- Single static binary per service → straightforward offline install, fewer release-readiness failure modes.
- Tiny Docker images (50–100 MB typical) → faster restricted-network distribution.
- Stdlib-heavy ecosystem → smaller audit surface for security review.
- Strong concurrency primitives → session broker and connector service scale to many thousands of concurrent sessions without architectural surgery.
- Stable, mature server stack (`net/http`, `chi`/`fiber`/`echo` for HTTP; `crypto/sha256` for chained hashes; `database/sql` for storage).
- Compatible with the existing schema-first contract: OpenAPI fragment (`docs/api-contracts/openapi.v3.fragment.yaml`) and 18 JSON schemas (`packages/shared-schemas/`) drive codegen for both Go and TS.

### Negative
- Shared types between Go and TS require codegen plumbing in CI (mitigated by `oapi-codegen` / `quicktype` and ADR-0042's monorepo orchestration).
- Less ergonomic for AI vendor SDKs than Python (mitigated by Python sidecar).
- Smaller hiring pool than TS for senior backend roles (mitigated by Go's straightforward learning curve).
- Capability-edge enforcement is type-checked but not compile-time-proved as in Rust (mitigated by strict tests + Permission Model Reviewer gate).

### Held in reserve
- A future hardened crypto / sandbox / kernel-adjacent module may justify Rust. If that need surfaces, file a follow-up ADR proposing the specific module's language exception. Default answer for new modules is Go.

## Verification

This ADR is verified once the following hold:

1. `services/audit-service` ships as a Go module producing a single static binary.
2. `docker build` against that service yields an image under 100 MB.
3. The image runs in a `scratch` or `distroless` container with no Node / Python runtime present.
4. The append-only audit endpoint passes its evidence-chain integrity test under concurrent load (target: 10k events / minute / instance with no dropped or out-of-order writes).
5. OpenAPI codegen produces matching Go server stubs and TypeScript client types from the same `openapi.v3.fragment.yaml` source.

## Review triggers

Re-open this ADR if any of these become true:

- The hiring market for Go specialists materially deteriorates relative to TS / Rust.
- A specific module's threat model demands stricter compile-time invariants than Go provides → propose Rust per-module ADR.
- A Go-specific supply-chain incident materially affects the project's trust posture.
- The P1+ AI sidecar design fails the audit-edge boundary and requires reconsidering Python's role.
