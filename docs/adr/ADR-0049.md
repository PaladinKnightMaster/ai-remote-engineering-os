# ADR-0049: Cockpit session audit content model (hash-in-chain + cast-anchored), broker-authoritative close, and v0.1.0 reconnect deferral

## Status

Accepted — 2026-05-31. **Refines ADR-0048 §6 (audit granularity) and §8 (TTL /
reconnect).** Does not modify ADR-0048; this is the new-ADR record of decisions
the SSH-slice implementation (T-016…T-020) made that ADR-0048's text did not
fully pin down, plus one deliberate deviation from a literal reading of §6.

## Context

ADR-0048 §6 specified a per-Enter `terminal.input.line` chained-hash event
carrying `{ session_id, line }`, plus `session.open`/`session.close`/
`session.terminated` lifecycle events and an asciinema cast hashed at close. §8
implied "fresh-prompt-on-reconnect."

Building the slice surfaced three points the ADR text left open and one
deviation that needs recording (CLAUDE.md: deviations from an Accepted ADR
require a new ADR, not an edit):

1. The `audit-service` ingest contract (ADR-0045) is **deliberately content-free**
   (`{timestamp, actor, edge, target, outcome?, evidencePacketId?, idempotencyKey}`)
   — there is nowhere to put a `line` payload without a schema change, and
   persisting raw operator input would freeze typed secrets (a password at a
   prompt) into the immutable chain.
2. Two components can end a session — `services/api` (REST control plane) and
   `services/session-broker` (WS data plane) — and `services/api` has **no
   outbox** (it emits no audit). Their close order was uncoordinated.
3. A transient WS drop and an intentional end are indistinguishable at the
   broker, but the SPA hook auto-reconnects — which only works if a drop does
   not end the session.

## Decision

1. **Audit content model: hash-in-chain + cast-anchored.** Cockpit audit events
   (`session.open`, `session.close`, `terminal.input.line`, `cast.pruned`) carry
   only `evidencePacketId = sha256:<bytes>` — never the raw bytes. Raw input +
   output live in the access-controlled asciinema cast file. This keeps §6's
   per-line operator-attribution and real-time tamper-evidence (each submitted
   line's hash is chained as it happens) while (a) needing no audit-schema change
   and (b) keeping secrets out of the immutable chain. Content is recoverable by
   hashing the cast's line back. **This refines §6's literal `{session_id,
   line}`** to `{session_id, sha256(line)}`.
2. **Broker-authoritative, finalize-once close.** The broker that held the live
   connection is the authoritative finalizer: `store.Close` keys on
   `cast_sha256 IS NULL`, so it records the cast SHA + emits `session.close`
   exactly once, regardless of whether `api.end` already set `status='closed'`
   (which is audit-silent control-plane intent). `ended_at`/`closed_reason` are
   COALESCEd so an api-set intent is preserved.
3. **v0.1.0 reconnect: a WS drop ends the session.** ADR-0048 §8's
   fresh-prompt-on-reconnect is **deferred to v0.2.0**. At v0.1.0 a broker WS drop
   ends + audits the session; `<TerminalView>` sets `reconnect:false`. (ADR-0048
   §item-8 always deferred reconnect/crash-recovery to the slice ticket.)
4. **`session.terminated` reserved-unused at v0.1.0.** All ends map to
   `status='closed'` with `closed_reason ∈ {operator, idle, broker_crash, ttl}`.
   The `terminated` status value is CHECK-allowed but unused, and no distinct
   `session.terminated` lifecycle event is emitted at v0.1.0.

## Alternatives considered

- **Raw line bytes in the chain (literal §6).** Rejected: persists typed secrets
  into the immutable forensic chain and requires extending the content-free
  `audit-service` ingest schema (forward-only migration + OpenAPI + chained-hash).
  The hash-in-chain model gives equivalent tamper-evidence with neither cost.
- **api as a co-equal closer (api also emits `session.close`).** Rejected at
  v0.1.0: would require an outbox in `services/api` and a dedup/coordination rule
  between two emitters. The broker already holds the cast SHA, so making it the
  sole finalizer is simpler and correct for the connected case.
- **Build full reconnect now.** Rejected for v0.1.0: per-connection cast files
  break the single-SHA-per-session anchor and add a reaper for abandoned
  sessions; MVP survival does not need it.

## Consequences

### Positive
- Privacy-preserving audit: no typed secrets in the immutable chain.
- No `audit-service` schema churn; reuses the ADR-0045 content-free ingest.
- The primary (UI/REST) end path is now correctly audited (was a silent gap).
- Smaller, honest v0.1.0 surface.

### Negative
- Cast content sits behind filesystem access control, not the chain — an
  investigator needs both the chain (attribution + integrity) and the cast
  (content). This is the intended split, but it is two stores.
- **Orphan-close audit gap:** a session closed only by `api.end` with no broker
  attached emits no `session.close`. Mitigation: a reaper/sweep is future work;
  documented in T-020a.
- No reconnect resilience at v0.1.0 — a network blip ends the session.

## Verification

- T-019a: `terminal.input.line` carries the SHA only; raw bytes never in the
  chain payload (integration-asserted).
- T-020a: finalize-once close records the cast SHA + emits `session.close` even
  after an api pre-close; `<TerminalView>` does not auto-reconnect.
- T-020b (pending): live docker-compose walkthrough asserts the full chain
  (`session.open` + `terminal.input.line` + `session.close` w/ cast SHA),
  closing ADR-0045 §Verification item 3.
