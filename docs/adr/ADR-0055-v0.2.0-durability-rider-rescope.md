# ADR-0055: v0.2.0 criteria amendment — the durability riders re-scoped (WD-2.5 / FE-9)

## Status

Accepted — 2026-06-11. **Amends `docs/evaluation/v0.2.0-release-criteria.md`
(WD-2.5 + FE-9) without editing it** — that document's own rule is "future
changes to this document require a new ADR"; this ADR is the amendment record.
It papers decisions already made at the T-032 authoring consult (CEO sign-off)
and re-confirmed at the T-033 scoping consult (2026-06-11); no new design is
introduced here.

## Context

The accepted criteria's §2 WD-2.5 names two "durability riders": (a) a dropped
WebSocket reconnects with a fresh shell (FE-9 makes it operator-visible), and
(b) a session orphaned by an api-only `end` is reaped "and emits its
`session.close`". Authoring T-032 surfaced that both, as written, conflict with
Accepted ADRs or require genuinely new design:

- **Reconnect:** the only ADR-0049-conforming form (fresh shell = a NEW session)
  would re-trigger the approval prompt on every transient blip for
  `requires_approval` resources — a UX regression the approval primitive itself
  created; a true resume contradicts ADR-0049 §3 and the single-cast-SHA
  evidence anchor and therefore needs its own ADR, not a rider.
- **Reaper-emitted `session.close`:** ADR-0049 §4 makes the broker the close
  authority (finalize-once, cast-SHA-anchored). An api-side reaper emitting
  `session.close` would create a second close authority without a cast anchor.
  Closing the true gap — a broker-crashed OPEN session's missing close — needs a
  **broker heartbeat** to tell live from crashed: a real feature, not a rider.

## Decision

1. **WD-2.5 narrows to the reaper as shipped (T-032):** an api-owned serve-time
   goroutine closes stranded PRE-OPEN sessions — `pending` → `ttl`,
   `pending_approval` → `approval_timeout` — **status-only** (no `session.close`
   emission; the broker remains the sole close authority per ADR-0049). Active
   sessions are never reaped.
2. **Deferred to v0.3.0** (named work, not silent drops): WS-drop reconnect (a
   dedicated design pass; if resume is wanted it needs a new ADR superseding
   parts of ADR-0049 §3), and the active-orphan audit-close via a broker
   heartbeat (the literal ADR-0049 documented gap).
3. **FE-9 defers with the reconnect rider.** FE-10 (bundle SLO) was re-verified
   at v0.2.0 regardless (138 KB gz first-load).
4. The criteria document itself stays **unedited**; release artifacts
   (`docs/releases/v0.2.0/`) report WD-2.5/FE-9 as "amended by ADR-0055".

## Alternatives considered

- **Ship WD-2.5 as written.** Rejected: requires either violating ADR-0049's
  close authority (a second `session.close` source) or landing an unscoped
  resume design inside a rider.
- **Record the re-scope in release notes only.** Rejected: the criteria doc's
  own amendment rule demands an ADR; criteria drift without a decision record
  is what the rule exists to prevent.
- **Hold v0.2.0 until reconnect + heartbeat land.** Rejected: both are additive
  durability features orthogonal to the release theme (governed egress), which
  is fully proven (WD-2.1–2.4 live on the compose harness and the installed
  stack).

## Consequences

### Positive
- The release gate's text and reality match again, with an auditable record.
- ADR-0049's single-close-authority invariant survives intact.
- v0.3.0 inherits two well-scoped, named work items with their design
  constraints already documented (T-032 ticket + this ADR).

### Negative
- A WS drop still ends the session at v0.2.0 (operator reconnects by starting a
  new session — re-approval included for flagged resources).
- A broker crash mid-session still leaves an OPEN session without its
  `session.close` until the v0.3.0 heartbeat work.
