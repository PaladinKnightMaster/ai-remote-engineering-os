## 2. Delta signals (what the reference set actually changes)

**The set VALIDATES the current strategy more than it overturns it** — the relevant clusters map
cleanly onto the existing 9 layers / 20 REQs. Five genuine deltas:

1. **Cockpit modality is real, buildable, and open-source-backed.** rustdesk + warpgate (remote
   desktop / bastion) and page-agent + browser-use (in-page / browser computer-use) confirm the
   terminal-only cockpit is a *deferred modality*, not a dead end. **Delta:** elevate GUI /
   computer-use / browser cockpit from "deferred" to a named near-term REQ, and decide Beta-1
   in/out. `page-agent` is notably doctrine-aligned (DOM-as-text, no multimodal, MCP server,
   bring-any-LLM, offline via Ollama).
2. **A self-hosted "companion external-services kit" is a NEW strategic idea** (your offline
   package note). The OS *integrates* self-hosted AppFlowy/AFFiNE/Excalidraw/rustdesk/gupt rather
   than cloning them — matches the exec-brief's "integrate existing tools first, full clones
   deferred." Candidate new blueprint section for the delta memo.
3. **L1 Context Index has concrete, doctrine-clean prior art NOW** (pg_durable, codegraph,
   codebase-memory-mcp, docling, files.md) — feeds **ADR-0066 (v0.10)** directly, no waiting.
4. **The governance moat is real and named by others** (microsoft/agent-governance-toolkit,
   NVIDIA/SkillSpector) — confirms audit/policy/approval/evidence is a recognized category, not a
   private bet. Reinforces positioning.
5. **The "runs no models" moat is reinforced, not threatened** — the large model-serving cluster
   is precisely what we deliberately don't build; we govern the agents that use them.

## 8. Deep-read findings — round 1 (2026-07-23)

### Cockpit modality (PRIORITY-1 — resolves the Beta-1 in/out question)
- **codemote** = terminal-only + **mobile supervision** (QR pairing, revocable tokens, encrypted
  phone↔PC devtunnel — no VPN/exposed SSH; live output + git-diff + approve/redirect). Runs no
  models. → The perceived computer-use gap is a **mirage**: the reference product is terminal+mobile,
  architecturally close to our governed terminal+approval. Missing pieces = a mobile approval client
  + QR pairing — **both already in our vision** (REQ-001 "mobile"; exec-brief QR-pairing constraint).
- **warpgate** = self-hosted **Rust** bastion proxying SSH/HTTP/K8s/MySQL/PG/**RDP/VNC**, full
  session recording + **command-level** audit, 2FA/SSO/OIDC, single binary, offline, SQLite. →
  Doctrine-aligned prior art for the **deferred GUI (RDP/VNC) cockpit** (ADR-0048). Post-Beta
  modality candidate (own ADR). Overlaps our session-broker+audit — reference, likely not a dep.
- **page-agent** = MIT in-page **DOM-as-text** browser agent (no screenshots/multimodal),
  bring-any-LLM incl. Ollama, ships an MCP server. **Web-app-embedded** (SaaS-copilot), NOT general
  PC control. → Post-Beta **browser** modality candidate (own ADR).
- **Incumbent-surface verification (CEO-prompted; the codemote pattern is TABLE-STAKES, not a
  differentiator):** BOTH frontier tools already ship it natively as of H1 2026 —
  - **Claude Code Remote Control** (preview, early 2026): mobile/web viewport into the *local*
    session; **spacebar→QR pairing** (the exact codemote flow); approve/redirect from phone; sync
    layer, not cloud migration. **Claude Tag** (Slack, 2026-06-23, Opus 4.8): @Claude channel
    dispatch, async, routes coding to web sessions.
  - **Codex in Slack** (GA early 2026): @Codex dispatch + result summary; Linear auto-assign.
    **Codex on ChatGPT mobile** (2026-05-14): start tasks / read output / inspect diffs / **approve
    risky commands** / switch model / notifications. Codex is **cloud-first** (remote sandboxes).
- **REVISED CONCLUSION (v2 — precise line; corrects an earlier over-broad "don't build mobile"):**
  Two different things hide under "mobile/QR" with OPPOSITE answers:
  - **DON'T rebuild** mobile remote-control of a *Claude Code / Codex agent session* — the agent tool
    owns that; the customer's agent brings it; reinventing it is the waste.
  - **DO build** self-hosted **QR pairing + mobile-responsive access to OUR operator surface**
    (approval console + cockpit). This is **an unshipped piece of the P0 cockpit promise**, not new
    scope: REQ-001 "browser/**mobile** GUI", Roadmap Phase-1 "**mobile controls**", exec-brief
    non-negotiable "**QR pairing** … short-lived state, never credentials". It's the natural home for
    our core act (approve-from-anywhere), and it's **doctrine-DIFFERENTIATED**: incumbents' mobile is
    cloud-relayed (Codex sandboxes / Claude→claude.ai) → breaks for the air-gapped buyer; ours is
    on-network, credential-free QR, fully offline — *"approve governed actions from your phone,
    air-gapped, no cloud relay."*
  - **Beta-1 scope:** mobile-responsive approval/cockpit web view + QR pairing (short-lived token,
    never creds) — NOT a native app (the Vite/React SPA is already responsive-capable); lands in the
    Beta-1 UX/onboarding pass. **First-class but CONFIGURABLE** (some locked-down SOCs forbid phones).
  - **Still deferred post-Beta (each own ADR):** Slack/mobile-channel *integration* connector
    (surface approvals into the customer's existing channels; non-air-gapped only; Slack=SaaS, not a
    dependency); GUI remote-desktop (warpgate RDP/VNC); browser computer-use (page-agent).
  - Differentiator restated: NOT the modality per se — it's that we deliver the expected surface
    **self-hosted + air-gapped + credential-free**, where the cloud-relayed incumbents can't.
- **Strategic two-sided read:** RISK — frontier tools commoditize the surface (even computer-use).
  REINFORCEMENT (bigger) — Codex cloud-first + Claude Tag→web move them AWAY from air-gapped/
  self-hosted, WIDENING our niche. Sharpest story: *"dispatch Claude/Codex as you already do, but
  execution is brokered through your self-hosted governance plane — credentials never leave, every
  action audited."* Integration, not rebuild.

### Hermes-agent (PRIORITY-2 — validates the moat by contrast)
Powerful, model-flexible runtime; **governance is WEAK** (allowlist command approval, DM pairing,
container isolation; **no RBAC, no formal audit chain, cloud-model-oriented** via Nous Portal). We
are the inverse (governance-first: chained audit, policy, approval, grants, edges; model-free).
**Borrow, don't become:** FTS5 full-text session memory + summarization (deterministic, no-embedding);
Tool-Gateway boundary (we have it — mcp-gateway); cron scheduler (validates the v0.7 Workstream
ticker); decoupled execution backends local/Docker/SSH/serverless (future broker-flexibility idea);
procedural-skills-from-experience (feeds the skill-hygiene meta-idea).

### L1 prior art (feeds ADR-0066 NOW)
- **codegraph** = the doctrine-clean L1 **reference implementation**: tree-sitter AST (nodes +
  edges: calls/imports/inheritance) → SQLite + **FTS5 full-text**, **NO embeddings**; incremental via
  OS file-watch (inotify/FSEvents) + 2s debounce; **per-file staleness banner**; single MCP query
  returns verbatim source + call paths + blast-radius (−89% tool calls, −69% tokens). 100% local. →
  **Borrow the mechanism** (tree-sitter parse / FTS / incremental-watch / staleness-signal /
  single-query), **wrap in OUR containment** (grant-scoped reads + per-read chained audit — the
  SEC-32 extension). We're Postgres → **Postgres FTS (`tsvector`/`tsquery`)** is the FTS5 analog.
  Index scope = repo/docs/tickets (AST for code; headings/frontmatter/ids for docs/tickets).
- **pg_durable** = durable SQL **workflow execution** in Postgres (checkpointing, crash-safe
  background work), deterministic, no embeddings. → **Mis-clustered — NOT an L1-index tool**; it's a
  durability/workflow reference relevant to the Run engine's crash-safety (already covered by our
  reclaimable-claim design). Low priority.
- **TWO independent confirmations (Hermes FTS5 + codegraph FTS5/tree-sitter)** that **deterministic
  full-text + structural parsing is the industry-proven, doctrine-clean L1 mechanism — no
  embeddings.** De-risks ADR-0066's no-embedding mechanism lock (D2).
